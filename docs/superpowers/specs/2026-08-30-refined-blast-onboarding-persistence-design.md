# 精细化爆炸工作台首次使用与状态恢复设计

日期：2026-08-30

## 目标

首次使用者进入 `/refined-building-blast` 后，应立即看懂“选择工况、配置、创建项目并保存、刷新轻量预览、验证、生成 K 包”的顺序。首次保存负责创建独立项目；后续保存只更新该项目。返回普通工作台再进入时，应恢复最近保存项目，未创建项目时也应恢复当前会话里的工况选择。

## 交互设计

- 页面首次进入显示四阶段流程卡，并把当前可执行阶段突出显示。
- 未建项时，右上角显示“待创建 · 首次保存将自动建项”，主按钮显示“创建项目并保存草稿”。建项后显示项目 ID 与 revision，按钮恢复为“保存草稿”。
- 建筑资产选择区显示三类真实工况的中文名称、结构概述、载荷传播方式和适用用途。载荷提供器选择区同步解释 ALE/FSI、LBE 与导入压力时程的差异。
- 页面保存最近项目 ID 到 `localStorage`；未建项的资产、结构、草稿保存到 `sessionStorage`。服务端项目始终是保存后数据的唯一真源。
- 返回普通工作台不清除恢复线索。再次进入时优先恢复 URL 项目，其次恢复最近项目，最后恢复未建项会话草稿。
- 提供“新建工况”按钮，显式清除恢复线索并重新挂载全新工况，避免用户被永久锁在最近项目。

## 错误处理

- 最近项目恢复失败时清除失效项目 ID，回到未建项界面并显示可理解的恢复提示。
- 浏览器存储不可用时静默降级为单次页面会话，不影响保存、预览、验证和生成接口。
- 未建项草稿不会冒充已保存项目；只有 POST `/projects` 成功后才显示“项目已创建”。

## 测试与视觉验收

- 静态合同覆盖流程卡、项目/草稿说明、三工况解释、新建工况控件。
- Node runtime 覆盖首次保存自动建项、最近项目恢复、未建项选择恢复、显式新建清理。
- 运行 Phase 18F Web 与状态回归测试。
- 启动本地服务，以首次使用者身份逐步操作，每一步保存一张截图；额外验证返回普通工作台后再次进入仍恢复相同工况。

## 非目标

不改变建筑编译、LS-DYNA provider 数学语义、K 包格式和求解器启动授权门禁。
