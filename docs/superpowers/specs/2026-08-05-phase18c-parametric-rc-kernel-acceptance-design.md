# Phase 18C 参数化钢筋混凝土内核验收设计

**状态：** 已批准，现作为 Phase 18C RC 结构后端验收条件
**日期：** 2026-08-05  
**范围：** 构件尺寸重建、钢筋同步重建及内部结构选择性生成

> **重构说明：** 本文保留为 `rc_frame`、`rc_frame_shear_wall` 和 `rc_box` 等 RC 后端的强制验收合同。Phase 18C 总体已扩展为建筑空间语义与多结构体系内核，现行设计见 `docs/superpowers/specs/2026-08-05-phase18c-f-multi-system-refined-building-blast-redesign.md`。

## 1. 设计结论

Phase 18C 不对 Phase 18A-1 提取的固定有限元拓扑进行拉伸。梁、柱、板、基础或墙体的长度、宽度、高度、厚度及网格尺寸发生变化时，内核必须从结构语义重新生成：

1. 混凝土八节点实体网格；
2. 适用于该构件的纵筋、箍筋、分布筋、板筋、墙筋或基础钢筋；
3. Beam 方向节点、Section 和 Material 绑定；
4. 钢筋—混凝土嵌入集合；
5. 外表面、边界及审计清单。

构件延长后，纵筋端点随有效构件长度更新；箍筋和分布筋的数量由目标间距、端部规则与加密区重新计算，而不是把原钢筋节点等比例拉长。

## 2. 生成模式

内核提供三个稳定模式：

- `full_reinforced`：生成混凝土、全部适用钢筋及嵌入耦合，作为精细化构件默认模式。
- `concrete_only`：只生成混凝土实体；钢筋单元数为零，钢筋资源依赖和嵌入耦合集合为空。
- `custom`：按角色分别启用纵筋、箍筋、板筋、墙筋、基础钢筋和对应耦合。

未生成钢筋时不得生成钢筋嵌入耦合。请求不存在的钢筋角色、在缺少钢筋时启用耦合、保护层无法容纳指定配筋等组合必须在生成前返回明确错误，不能静默降级或修改输入。

## 3. 输出合同

三种模式使用同一输出 schema。`reinforcement_manifest` 必须记录请求模式、实际生成角色、单元数量、被省略角色及原因；`embedded_coupling_sets` 在无钢筋模式下必须是合法空集合。相同规范化输入必须生成相同的稳定 ID、资源清单和 `fidelity_fingerprint`。

## 4. 验收测试

Phase 18C 至少通过以下自动化夹具：

1. 梁、柱、板、基础和墙体分别改变一个及多个尺寸后，证明 Solid 拓扑按新尺寸重建。
2. 构件延长后，纵筋有效长度、保护层、箍筋/分布筋数量、普通区间距和加密区间距满足输入合同。
3. `full_reinforced` 同时产生 Solid、适用 Beam 和依赖闭合的嵌入集合。
4. `concrete_only` 产生 Solid，但 Beam 数为零且嵌入集合为空。
5. `custom` 对每个适用钢筋角色执行开关组合测试，只生成明确启用的角色。
6. 对缺少钢筋却请求耦合、保护层冲突和非法间距等输入执行失败测试。
7. 对每种模式执行确定性、稳定 ID、无悬空引用和清单一致性测试。

## 5. 工程边界

通过上述验收代表参数化几何、网格、依赖和软件合同成立，不代表材料卡、网格尺度或构件响应已经完成工程标定。工程使用仍需项目级审核、网格敏感性验证和真实求解证据。
