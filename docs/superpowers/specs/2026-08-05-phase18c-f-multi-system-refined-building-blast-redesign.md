# Phase 18C–18F 多结构体系精细建筑与独立爆炸工况重构设计

**状态：** 用户已批准总体方向，写入 Phase 18 优化路线
**日期：** 2026-08-05
**范围：** Phase 18C、18D、18E 和 18F

## 1. 问题与设计结论

旧有建筑是用外轮廓壳体表达的轻量资产。如果直接将外壳实体化，内部房间、走廊、中庭、井道和洞口会被 Solid 单元填满，建筑质量、刚度、破坏模式和爆压传播路径都会严重失真。因此，精细建筑不能从旧壳网格加厚、拉伸或填充获得，必须从建筑空间与结构语义重新生成。

设计采用：

```text
建筑空间语义模型
  + 多结构体系生成器
  + 非承重构件层
  + 独立可配置爆炸工况编译器
  + schema 驱动的设计与验证工作台
```

原 Phase 18C 的钢筋混凝土参数化重建与可选钢筋验收条件继续有效，但只属于 RC 结构后端，不再代表整个建筑内核。

## 2. 总体数据合同

```text
RefinedBuildingProject
├─ BuildingDefinition
│  ├─ envelope
│  ├─ storeys_and_grids
│  ├─ spaces_and_connectivity
│  ├─ openings_and_shafts
│  └─ structural_system_profile
├─ NonStructuralDefinition
├─ FidelityProfile
├─ BuildingArtifact
├─ ScenarioSet
├─ SolverProfile
└─ OutputProfile
```

建筑资产只负责空间、结构、材料、网格和可暴露表面。爆源、空气域、边界、FSI、求解控制和输出属于工况，不得固化进建筑资产。

## 3. Phase 18C：建筑空间语义与多结构体系内核

### 3.1 子阶段

1. **18C-1 空间语义内核**：楼层、轴网、房间、走廊、中庭、核心筒、楼梯、电梯井、门窗、楼板洞口、围护和空腔连通拓扑。
2. **18C-2 结构体系注册表**：`rc_frame`、`rc_frame_shear_wall`、`steel_frame`、`steel_concrete_hybrid`、`rc_box` 和 `custom_hybrid`。
3. **18C-3 RC 结构后端**：混凝土 Solid、纵筋、箍筋、板筋、墙筋、基础筋和嵌入关系。
4. **18C-4 钢结构与组合结构后端**：钢梁柱、钢板、节点连接、组合楼板、剪力连接和界面关系。
5. **18C-5 RC 箱体、基础与非承重构件**：地下/半地下箱体、承台/筏板、填充墙、隔墙、幕墙、门窗和屋面围护。
6. **18C-6 网格、表面、清单与稳定装配**：体系专属网格规则、局部加密、稳定 ID、材料/截面/连接闭包、规模预测和质量门禁。

### 3.2 可暴露表面合同

建筑内核输出 `fluid_exposed_surface_catalog`，至少区分：

- 建筑外表面；
- 内部空腔表面；
- 洞口边界；
- 地面/基础接触面；
- 用户可选表面集。

建筑内核不固定某一个 FSI 集合。内部、外部或半封闭工况根据空气连通性选择实际 `air_wetted_surfaces`。

### 3.3 不可绕过的验收条件

- 空腔、房间、走廊、井道和洞口内不得存在误填充 Solid。
- 结构体系改变后必须重建构件、连接、材料、网格和清单，不得仅替换材料卡。
- RC 构件尺寸变化后重建 Solid 与钢筋；保留 `full_reinforced`、`concrete_only`和 `custom` 验收条件。
- 钢结构端点、节点与连接无悬空、无重复引用；连接简化等级必须显式记录。
- 非承重构件不得因未声明共节点而获得虚假承载能力。
- 建筑质量、实体体积、空腔体积、单元数和清单一致。

## 4. Phase 18D：旧建筑的多体系精细语义重建

精细资产统一使用 `detailed_building` 能力标识，并另存 `structural_system_profile`；不再把所有建筑写成 `detailed_rc`。

| 建筑资产 | 默认候选体系 | 允许备选 |
| --- | --- | --- |
| 商业超市 | 钢框架＋RC 基础/楼板 | RC 框架、钢—混凝土混合 |
| 住宅建筑 | RC 框架—剪力墙 | RC 框架、剪力墙体系 |
| 地铁入口 | RC 箱体 | RC 框架—墙板组合 |
| 双层参考模型 | RC 框架 | 保持来源复现基准 |

旧轻量建筑的 ID、几何和默认调用不变。“从旧建筑创建精细项目”只允许复制资产身份、占地尺寸、高度和方位；不复制旧网格、内部结构推断、爆炸工况或求解结果。

保真档位为：

- `structural_core`：主体承重结构和主要洞口；
- `blast_response`：增加影响爆压传播或飞散物的围护、隔墙和门窗，作为默认；
- `research_detailed`：增加局部节点、连接细节和用户指定的次要构件。

原 RC `coarse/standard/fine` 网格值保留为 `rc_reference_profile`；钢结构、组合结构、连接区和非承重构件使用独立待审核网格规则。

## 5. Phase 18E：独立、可配置的精细爆炸工况引擎

### 5.1 独立项目边界

使用独立项目类型 `refined_building_blast@1`，拥有自己的 schema、存储目录、工具/API 命名空间、编译器、验证器、预览适配器、缓存、结果 ID 和失效规则。

与其他爆炸工况的关系是：

- 不调用、不继承、不修改其他工况生成器；
- 不读取其他工况的对象数组、布局草案、工况参数或求解结果；
- 只共享中性材料库、截面库、模型资源库、网格原语、关键字底层写入器和通用检查核心；
- 使用依赖边界测试禁止精细包与其他工况包互相导入。

### 5.2 首发载荷提供器

1. `explicit_ale_fsi`：显式建模炸药、空气域、起爆和流固耦合，用于高保真工况。
2. `lbe_segment`：通过经验爆压对选定表面施加载荷，用于快速预览、参数筛选和对比。
3. `imported_pressure_history`：导入试验或外部计算得到的压力—时间数据，并显式映射到表面集。

三者实现同一 `BlastLoadProvider` 合同，但各自拥有独立 schema、验证器、关键字片段和证据清单。不支持的组合必须明确拒绝，不得静默降级。

### 5.3 模块化编译流水线

```text
ScenarioDraft / Preset + Overrides
  -> BuildingPlacementCompiler
  -> SupportAndGroundCompiler
  -> BlastSourceCompiler
  -> FluidDomainCompiler
  -> BoundaryCompiler
  -> InteractionAndFSICompiler
  -> SolverControlCompiler
  -> OutputRequestCompiler
  -> ProjectAssembler
  -> CrossModuleValidator
```

每个模块只接收结构化输入，输出不可变关键字片段、依赖和 manifest；不直接修改其他模块状态。最终装配器负责统一 ID 空间、Include 顺序和跨模块闭包。只修改爆源时不重建建筑网格；修改结构体系时才使建筑及下游工况结果失效。

### 5.4 用户可配置层级

1. **内核不变量**：单位、ID 唯一性、依赖闭包、基本网格质量、爆源包含和非法重叠等不允许绕过。
2. **审核预设**：建筑原型、结构体系、材料组合、网格、空气域、爆源和输出预设。
3. **项目级覆盖**：轴网、层高、构件、洞口、材料、连接、网格、装药、起爆、空气域、支承、控制和输出。
4. **专家扩展**：用户材料、局部网格区、结构化覆盖和受控 Include；必须经过关键字允许列表、路径隔离、ID 冲突和依赖闭包检查，并记录来源。

同一建筑的 `ScenarioSet` 可包含外部、内部、半封闭和参数组合工况。每个工况独立生成、独立指纹、独立结果，不把多个工况写死在同一 K 文件。

## 6. Phase 18F：schema 驱动的设计工作台与验证闭环

工作台不固定为一套不变的六步向导。它依据建筑体系和载荷提供器的 schema/能力动态显示：

1. 建筑空间与洞口；
2. 结构体系与承重构件；
3. 钢筋、钢构连接或组合连接；
4. 非承重构件；
5. 材料、截面和失效模型；
6. 网格与局部加密；
7. 载荷方式、爆源、空气域、边界、相互作用和输出；
8. 错误/警告、规模预算、版本确认和生成。

“审核预设→结构化覆盖→专家扩展”三层交互共用同一数据真源。预览需分层显示空腔、主体结构、钢筋/连接、非承重构件、内外流体暴露面、爆源、空气域和边界。

草案、预览、正式生成、打开 LS-PrePost 和启动 LS-DYNA 仍是独立动作；外部打开和求解必须保持用户逐次授权。

## 7. 代码边界

推荐分为两个顶层包：

```text
refined_building/   # 建筑空间、结构体系、构件、网格与 BuildingArtifact
refined_blast/      # 工况、载荷提供器、空气域、FSI、控制、输出与装配
```

禁止继续向现有大型 `dyna_assembly.py`、`schema.py` 或通用工具模块堆叠精细场景逻辑。固定 Phase 18A-1 K 资源只用于对照、回归和刚体实例化，不通过拉伸或缩放冒充参数化构件。

## 8. 验证与工程边界

- 所有结构体系先通过最小构件和最小建筑夹具，再进入资产生成。
- 网格无负体积、重复单元、缺失节点和未声明间隙；硬错误不可被用户忽略。
- FSI 仅使用当前工况真实浸润的表面；内部工况依据洞口状态和空腔连通性生成集合。
- 爆源必须位于允许的流体域中且不与结构非法重叠。
- 规模预测的节点/Solid/Beam/Shell 数和最终清单一致，生成前显示内存、文件和时间步预算。
- 同一规范化输入、资源版本和模块版本产生相同指纹；只修改某个工况不改变建筑工件指纹。
- 通过软件验收不等于材料、网格或破坏预测已获得工程标定。

## 9. 需要用户分批审核的规范

1. 各建筑原型的默认结构体系和允许替代体系。
2. 适用的混凝土、钢结构、组合结构、防护和爆炸设计规范名称及版本。
3. 默认轴网、层数、层高、承重构件和非承重构件范围。
4. RC 配筋、钢构节点、组合界面和连接简化等级。
5. 各结构体系的网格档位、连接区加密和质量阈值。
6. 外部、内部和半封闭爆炸的默认工况参数与允许范围。
7. ALE 空气域、边界、FSI、LBE 表面选择和压力时程映射规则。
8. 最大节点/单元、内存、文件大小和计算预算。
9. 材料标定、网格敏感性、试验对照指标和允许误差。

未经审核的预设只能标识为研究/流程验证候选，不得标识为工程验证模型。
