# 场景求解稳定性修复设计

## 目标

以已经能够正常求解的 `rebar_drop_on_helmet` 为基准，修复 `rod_impact_plate`、`cube_top_corner_load` 和 `plate_pressure` 的建模及数值稳定性问题，并让静态检查能够阻止已知无效场景被标记为 solver draft ready。

## 范围

- 将杆撞板改为四周固支的可变形钢板。
- 将立方体从单个减缩积分实体单元改为至少 `4 x 4 x 4` 的规则网格。
- 将立方体集中力和压力板均布压力改为从零开始的线性渐进加载。
- 为立方体和压力板配置显式小时玻璃控制及能量统计。
- 修正装配场景壳厚/网格比检查，使其使用组件自己的网格尺寸。
- 增加场景语义检查，拒绝把可变形壳板全部节点固定。
- 增加受控 LS-DYNA 求解结果判据和解析单元测试；真实求解仍作为本机集成验证，不在普通单元测试中强制运行。

不修改 `rebar_drop_on_helmet` 的物理模型，不把 `uuc_like_single_element_demo` 注册为自然语言场景，不引入开放式原始 keyword 注入。

## 场景设计

### 杆撞板

平板保留 `shell_plate`、弹性材料和面面接触。固定边界由 `z_min` 改为 `x_min`、`x_max`、`y_min`、`y_max`，使平板周边六个自由度受约束、内部节点可变形。生成后检查固定节点数必须小于平板节点总数，并且至少存在一个未约束内部节点。

### 立方体四角加载

默认网格尺寸取最短边的四分之一，使每个方向至少有 4 个单元。顶面四角节点不再使用固定 ID，而是通过几何选择器在生成网格后解析。载荷曲线从 `(0, 0)` 线性增长到 `(1 s, -corner_force_n)`。模型启用 `CONTROL_ENERGY`、`CONTROL_TIMESTEP` 和显式小时玻璃定义，避免单个 ELFORM 1 单元的零能模式主导结果。

### 压力板

保留左边固支的悬臂壳板语义。压力曲线从 `(0, 0)` 线性增长到 `(1 s, pressure_pa)`，启用 `CONTROL_ENERGY`、`CONTROL_SHELL`、`CONTROL_TIMESTEP` 和壳单元小时玻璃控制。默认压力和终止时间保持不变，以避免无关 API 变化；是否达到准静态状态由求解结果判据决定，而不是仅依赖正常终止。

## 校验设计

静态检查新增以下规则：

- 装配场景壳厚/网格比按每个壳组件的 `geometry.thickness_m / mesh.size_m` 计算。
- 可变形壳组件的固定节点集合不得覆盖该组件全部节点。
- 场景生成结果必须包含要求的控制卡、渐进曲线和非退化网格数量。

求解结果解析器从 `d3hsp` 提取终止状态和能量块。场景准入至少检查：

- 必须正常终止，且不存在 error termination、NaN 或 negative volume。
- 内能不得为负。
- 小时玻璃能占物理内能或初始动能的比例不得超过场景阈值。
- 准静态场景末期动能/内能比例必须低于阈值。
- 冲击场景总能量比必须接近 1，并确认接触能量或接触状态出现。

普通 `checks.json` 继续明确其静态范围；没有真实求解产物时不伪造 solver-verified 状态。

## 错误处理

- 无法解析 `d3hsp` 时返回明确的未验证状态，不降级为通过。
- 能量分母接近零时使用绝对值和替代基准，避免除零。
- 真实集成测试继续通过环境变量显式开启，并在隔离目录运行。

## 测试策略

1. 先增加失败测试，覆盖四周固支、至少 `4 x 4 x 4` 网格、渐进曲线、小时玻璃控制和组件网格比。
2. 增加 `d3hsp` 解析器夹具，覆盖正常终止但能量失稳、负内能、小时玻璃能过大和有效求解。
3. 运行全部 Python 单元测试与 `compileall`。
4. 使用本机 LS-DYNA 对三个正式场景重新求解；只有能量判据通过才将场景标记为修复完成。

## 成功标准

- 三个正式场景均能由当前生成入口生成并通过静态检查。
- 杆撞板存在未固定的平板内部节点。
- 立方体不再是单单元模型，且真实求解不出现负内能或小时玻璃能主导。
- 压力板真实求解小时玻璃能不主导物理内能，准静态指标满足设定阈值；若默认载荷仍无法满足，则继续调整网格、单元控制或加载时间，不能仅以正常终止宣告通过。
- 基准场景与 UUC 单元测试回归不退化。
