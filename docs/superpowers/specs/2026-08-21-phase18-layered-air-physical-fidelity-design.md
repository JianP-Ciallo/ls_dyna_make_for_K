# Phase 18 分层空气域、真实建筑细化与传播验收设计

状态：用户已确认分节设计，待书面规格复核

日期：2026-08-21

单位制：`SI_m_s_kg_N_Pa`

## 1. 文档目的与优先级

本设计升级 Phase 18 三类精细建筑爆炸模型，使商业超市、住宅建筑和地铁入口同时具备：

1. 有现实承重路径、实体体积和可审计连接的建筑结构；
2. 可见且有物理含义的 MM-ALE 空气域；
3. 位置、当量和起爆时刻可修改的显式 TNT 实体；
4. 经真实暴露面 FSI 把能量按“炸药 → 空气 → 建筑”传递的求解链；
5. 从前端配置到 LS-PrePost、LS-DYNA R12 和 1 ms 传播验证的可追溯证据。

本设计是对下列既有规格的增量修订，冲突时以本文为准：

- `2026-08-20-phase18-solver-complete-ale-fsi-buildings-design.md`；
- `2026-08-21-phase18-solver-physical-detail-ground-mesh-design.md`；
- `2026-08-21-phase18-explicit-tnt-fidelity-design.md`。

特别修订：**45–70 MiB 仅是代表性验证模型的观察性软指标，不是通过/失败门槛。** 不允许为了进入该区间而生成无物理意义的网格、记录或填充；模型合理小于 45 MiB 或大于 70 MiB，只要物理、预算和求解门禁全部通过，仍可接受。

## 2. 设计原则与总体架构

采用“分层物理域 + 暴露面 FSI”方案。求解模型由五个语义互斥但数值上可耦合的域组成：

1. `active_air`：真实空气，承载质量、压力、内能和冲击波；
2. `explicit_tnt`：显式 TNT HEX8 实体和起爆定义；
3. `coupling_buffer`：地坪附近的 1–5 层 ALE 耦合缓冲网格，不是自由空气传播通道；
4. `soil_ground`：实体土体和地面；
5. `building_structure`：建筑 Solid、Shell、Beam 及其连接。

MM-ALE 背景网格允许与 Lagrangian 结构在几何上重叠，以支持 `*CONSTRAINED_LAGRANGE_IN_SOLID`；但物理分类、材料初始化和暴露面提取必须保证重叠网格不会被误解释为建筑下方的自由空气走廊。

建筑、空气、TNT、土体、边界、材料、连接、测点和求解配置均由一个规范化场景产生。前端、预览、K 包、清单、验证和求解不得拥有互相矛盾的私有真值。

## 3. 分层空气域和地面合同

### 3.1 空间范围

空气域的 XY 范围必须覆盖建筑、真实开口、爆源和传播所需空间，并在四个侧面保留相互独立、可配置的余量。空气域不要求与混凝土投影完全重合；合理侧向余量用于冲击波传播、绕射和非反射边界隔离。

Z 方向满足：

- 顶部高于屋面、爆源和最高传播区域；
- 自由空气不得向地坪下无限包裹；
- 地坪下只允许 1–5 层 `coupling_buffer`，默认 2 层；
- 缓冲深度等于层数乘以当地空气网格尺寸；空气单元为 0.225 m 时范围为 0.225–1.125 m；
- 地铁入口内部的地下空气只在与真实入口、楼梯井或通风开口连通时属于 `active_air`；
- 地铁地下箱体外侧及底部属于土体接触，不属于外部空气。

### 3.2 表面分类

每个结构边界面必须且只能属于下列一种分类：

- `external_air_exposed`：与外部有效空气连通，可进入 FSI；
- `internal_air_exposed`：与内部有效空气连通，可按工况进入 FSI；
- `soil_contact`：与土体接触，不得进入空气 FSI；
- `sealed_internal`：封闭内部面，不参与外部传播；
- `structural_connection`：构件连接界面，不参与空气 FSI。

分类必须从真实单元拓扑、材料域和连通性计算，不得仅依赖资源目录标签。分类不完整、重复或冲突均为硬错误。

### 3.3 连通性与隔离

对 `active_air` 进行三维 flood-fill：

- 外部空气必须能从爆源传播到声明的外暴露面；
- 基础底面、地下外墙和土体接触面不得存在来自外部空气的自由连通路径；
- `coupling_buffer` 是允许与近地结构几何重叠的 ALE 背景单元，但不初始化为空气或 TNT 材料；它不得包含空气质量、TNT、测点或可作为传播通道的有效体积分数；
- TNT 必须完整位于 `active_air` 内并与建筑、土体和外边界保持经网格解析的正安全距离；
- 结构、土体、空气和 TNT 不得存在未声明的正体积材料重叠或空洞。

### 3.4 外边界

四个侧面和顶部使用相互独立的边界集合，默认采用经 R12 小模型验证的非反射/流出近似。它们不是数学意义上的完美无反射边界，必须通过边界距离和回波测点审查其影响。

底面不得与侧面共用流出集合。底部采用封闭的结构/土体边界；具体 R12 卡片先在独立小模型中验证，再进入三类大型模型。实现不得在未验证时凭经验选择卡片。

## 4. 结构单元与连接原则

允许 Solid、Shell 和 Beam 在同一模型中共存。禁止的是缺少物理依据的混用，而不是禁止某个单元族。

- 大体积混凝土墙、柱、梁、楼板、基础、地下箱体和土体采用 Solid；
- 薄钢屋面、玻璃和薄围护板采用有真实厚度的 Shell；
- 钢筋、箍筋、细长钢梁、檩条和栏杆采用有真实截面的 Beam；
- 不满足薄壁或细长假设的局部构件改用 Solid，或记录经审查的例外依据。

连接规则：

- Solid–Solid 优先共享节点；不共形时使用经小模型验证的 tied/contact；
- 钢筋使用独立节点和明确的 embedded 约束，不与 Solid 复用节点，避免 Beam/Solid 共享节点导致的 R12 错误；
- Shell/Beam 到 Solid 使用可审计的插值、焊接或 tied 连接；
- 不允许仅在画面中相交、悬空、重复承重、未声明穿透或无宿主钢筋。

每个承重构件必须进入连续荷载路径：

`屋盖/墙体 → 梁板 → 柱/剪力墙 → 基础 → 土体`

## 5. 三类建筑的物理细化

### 5.1 商业超市

- 由可配置跨距和轴网生成真实结构网格；
- 轴网交点布置 Solid RC 承重柱，柱内含独立纵筋和闭合箍筋；端部及连接区允许加密箍筋；
- 梁、屋架、檩条和屋面形成连续支承，并把荷载传至 RC 柱和基础；
- 基础采用筏板、承台/独立基础和必要的地梁，底板与土体接触；
- 实体外墙含横、竖双向配筋，门窗洞口避让并设置边缘、过梁或洞口加强；
- 非承重隔墙和承重墙分开建模；
- 薄钢屋面可用 Shell，钢梁和檩条可用 Beam，但必须有截面、方向和连接证据；
- 自动检查每根柱的混凝土宿主、纵筋、箍筋、保护层、轴线归属及从屋面到基础的路径。

### 5.2 住宅建筑

- 采用 RC 框架–剪力墙体系，楼板、梁、柱、剪力墙和核心筒连续；
- 关闭无设计依据的空层和水平断带；楼层空洞仅可来自明确的楼梯井、电梯井、设备井或洞口；
- 设置核心筒、连梁、楼梯段和平台，并验证支承；
- 剪力墙边缘构件、洞口加强和阳台支承明确建模；
- 采用筏板或条形基础并与土体建立可审计接触；
- 内部空气按房间、走廊、门窗、楼梯井的真实连通关系构造，不得穿过封闭楼板或墙体；
- 自动检查上下层竖向构件对齐、楼板支承、阳台/楼梯无悬空以及空气仅通过真实开口进入。

### 5.3 地铁入口

- 地下底板、侧墙、顶板、加腋、井道、挡墙、楼梯段和平台采用 RC Solid；
- 地下箱体外侧及底部与实体土体接触，禁止进入外部空气 FSI；
- 内部空气只通过真实出入口、楼梯井或通风开口与外部连通；
- 地上亭体的不透明墙和屋盖采用有实体体积的 Solid；玻璃采用 Shell，框架、栏杆和钢筋采用 Beam；
- 地面标高、开挖体、回填土和结构不得重叠；
- 自动检查入口通行净空、楼梯/平台支承、亭体边缘连接和地下空气连通路径。

## 6. 材料与工程边界

每种材料记录：材料卡族、密度、弹性模量、泊松比、屈服/破坏/率效应参数、来源、单位、适用范围及校准状态。

提供两个明确档案：

- `verification_reference`：字段完整、单位闭合的研究/软件验证参数；
- `project_calibrated`：由具体项目试验、规范或工程审查提供的参数。

未使用 `project_calibrated` 或未完成网格/材料/工况校准时，产物保持：

- `engineering_validated=false`；
- `solver_ready=false`；
- `requires_project_review=true`。

短时正常求解只证明该快照的初始化和波传递链可运行，不证明峰值压力、损伤、倒塌或安全结论已获得工程验证。

## 7. 规模与预算策略

系统提供两类模型：

1. 代表性验证模型：保留足以验证承重路径、空气、TNT、FSI 和连接的物理细节，便于自动回归和 1 ms 求解；
2. 项目模型：允许按跨数、层数、塔楼数、地下长度和局部细化扩展，由显式资源预算限制。

45–70 MiB 仅记录为代表性模型的软指标。真正的硬门禁包括：

- 节点、Solid、Shell、Beam、面、集合和总记录数预算；
- 预估内存、生成时间和求解时间预算；
- 大分配前的解析下界/上界检查；
- 网格质量、物理细节、材料和连接闭合；
- LS-PrePost、mcheck 和求解结果。

系统不得自动放粗用户要求的关键区域，也不得通过文本格式、重复记录、注释或无效单元改变文件体量。

## 8. 检测资源与分级门禁

### 8.1 几何与网格

- 所有 Solid 检查体积和八个自然角点的正 Jacobian，并检查长宽比和畸变；
- Shell 检查厚度、法向、重复面和局部长厚比；
- Beam 检查长度、截面、方向和零长度；
- 检测重复单元、未使用节点、材料重叠、异常间隙和悬空构件；
- 钢筋检查保护层、间距、箍筋闭合、宿主包含和洞口避让。

### 8.2 结构荷载路径

构建构件图，验证所有声明的承重屋面、墙、梁、板、柱、剪力墙、基础和土体均能进入连续荷载路径。断链、重复承重语义或无支承构件为硬错误。

### 8.3 空气、TNT 与 FSI

- 执行 active-air flood-fill 和 buffer 隔离检查；
- 验证 TNT 几何、质量、位置、安全包络和 ALE 分区；
- 验证表面分类完整且互斥；
- FSI 面必须是真实定向边界面、面积非零、节点有效并邻接 active air；
- FSI 面不得同时属于土体接触、结构连接或密封内部面；
- 检查空气/TNT 质量、体积和材料初始化守恒。

### 8.4 边界、测点和能量

默认测点覆盖爆源、近场、屋面、上/下层外墙、室内、基础和远场边界。检查：

- 压力到达顺序和传播方向；
- 侧面/顶部边界的回波和反射时间；
- 爆炸、空气、结构、接触和沙漏能量；
- ALE 质量/能量泄漏；
- 负体积、异常时间步下降、NaN 和发散。

边界距离和关键网格尺寸按需做敏感性比较。响应差异 5% 等数值只能作为软件初始参考，不是通用工程标准。

### 8.5 阈值策略

采用“严格的软件默认值 + 项目可覆盖值”。覆盖必须记录原值、新值、理由、作用范围和审核人。不得通过放宽阈值隐藏拓扑、几何、关键字或求解错误。

## 9. 前端体验

前端采用四个步骤，隐藏原始 JSON，常用参数直接显示单位、范围和解释：

1. **建筑配置**：资产、结构体系、跨数/层数、构件尺寸、材料档案、配筋、地面和局部网格；
2. **空气域与爆源**：TNT 当量、实体尺寸、X/Y/Z、起爆时刻、四侧/顶部余量、空气/近场/地面网格、1–5 层缓冲、内部空气开口；
3. **检查与预览**：分层显示 Solid、Shell、Beam、钢筋、土体、active air、buffer、TNT、FSI 面、边界和测点；
4. **生成与求解**：按门禁状态启用保存、生成、导入、mcheck、短时和 1 ms 操作。

空气域默认半透明可见，用户可隐藏。`active_air` 与 `coupling_buffer` 使用不同颜色和图例。爆源移动后预览立即更新；越界、碰撞、埋入土体或分辨率不足时阻断保存或生成。

高级参数默认折叠。任何参数变化都会使旧预览、确认、生成包和求解证据失效；不得把旧快照的 PASS 显示在新草稿上。

主表单的基础范围为：

- TNT 当量 `0.1–100 kg`，默认 `2 kg`；
- 爆源中心 X/Y/Z 为有限 SI 坐标，实际可用范围由当前空气域、TNT 实体尺寸和安全间距动态收紧；
- 空气单元尺寸 `0.15–0.50 m`；
- 地面单元尺寸 `0.10–0.50 m`；
- 地坪下耦合缓冲 `1–5` 层，默认 `2` 层。

软件允许输入范围不等同于全部工程验证范围。偏离默认验证工况后必须重新执行预算、网格分辨率、边界距离和求解审查。

## 10. 版本、身份和兼容性

现有 `phase18.solver_blast.config@3` 升级为闭合的 `phase18.solver_blast.config@4`。`@1`、`@2` 和 `@3` 只接受其各自精确字段，并通过唯一迁移补入新默认值；未知字段继续拒绝，已经发布的 `@3` 字段语义不得原地改变。

下列内容进入规范化场景和指纹：

- 建筑参数、结构体系、材料档案和网格；
- active air、buffer、soil 和 TNT 的范围与离散；
- 表面分类、FSI、边界和测点；
- 检查阈值、求解控制和 R12 求解器身份。

兼容原则：

- 旧 Phase 17/18 项目仍可读取、查看和归档；
- 旧包不得自动获得真实传播能力标记；
- 迁移后必须重新生成、重新验证；
- Phase 18D 固定资产 ID 保持稳定；
- 物理模型升级造成的指纹变化必须经过明确基线更新，不得静默漂移；
- 验收矩阵覆盖 Phase 17、Phase 18A–F、核心工具、打包和 Web 边界。

## 11. 生成与求解数据流

```text
前端草稿
  → 闭合 schema 规范化与预算预检
  → 建筑/空气/TNT/土体生成
  → 几何、连接、表面和拓扑审计
  → 确定性 K 包与 manifest
  → LS-PrePost 导入
  → LS-DYNA R12 mcheck
  → 0.05–0.1 ms 启动测试
  → 1 ms 传播验证
  → 必要的网格/边界敏感性比较
  → 机器可读和中文验收报告
```

每一级失败即停止后续操作，并报告构件、单元、坐标、关键字或日志位置。LS-PrePost 和 LS-DYNA 只在用户明确确认后启动；启动前再次核验工作目录、求解器路径、include 闭包和文件哈希。

耗时检查按精确不可变指纹缓存；只允许复用同一输入、同一 K 包、同一求解器版本和同一验证配置的证据。三类大型模型严格串行运行，避免资源争用制造假超时。

## 12. 输出包与证据

每个模型包至少包含：

- 主 K 文件和完整 include 闭包；
- 规范化输入、模型/材料清单和生成指纹；
- 网格、荷载路径、配筋、空气拓扑、FSI 和边界报告；
- LS-PrePost 导入、R12 mcheck、短时和 1 ms 日志；
- 压力、能量、结构响应和测点摘要；
- 所有文件的 SHA-256、字节数和记录计数。

证据必须绑定精确 K 文件、场景指纹、求解器版本、命令参数和完成状态。终端输出丢失、进程被中断或只有历史结果时，不得声称 fresh PASS。

## 13. 分级验收

每个模型依次通过：

1. 静态 schema、预算、几何、材料和连接审计；
2. LS-PrePost 导入零错误；
3. R12 `mcheck` 无未审查 Error；
4. 0.05–0.1 ms 启动测试正常终止；
5. 1 ms 求解正常终止，空气和建筑出现有限非零响应；
6. 压力传播满足爆源先、空气后、建筑再响应的因果顺序；
7. 无 NaN、fatal error、未接受的负体积或异常能量；
8. 必要的网格和边界敏感性结果在项目阈值内。

最终保留三份独立终态证据：

- 商业超市 + 显式 TNT/ALE/FSI；
- 住宅建筑 + 显式 TNT/ALE/FSI，并保留导入压力时程兼容测试；
- 地铁入口 + 显式 TNT/ALE/FSI，并保留 LBE 兼容测试。

LBE 和导入压力时程证明载荷链兼容性，不能替代显式空气域中的炸药传播证据。只有三份 fresh、可保存、未中断的终态记录均通过，才可称为“三项齐全的最终 PASS”。

## 14. 实施边界

本设计不包含：

- 为达到文件体量目标而无意义加密；
- 把 1 ms 结果称为完整抗爆、破坏或倒塌结论；
- 未经试验/规范校准即发布工程安全结论；
- 以隐藏警告、放宽阈值或删除真实构件换取通过；
- 自动启动外部工程程序；
- 静默改写旧资产 ID、旧项目或历史验证证据。

本设计完成后的能力目标是：Phase 18 能稳定生成具备实体建筑、可见 active air、1–5 层耦合缓冲、可移动显式 TNT 和真实 ALE/FSI 波传递链的模型；软件与短时求解通过后，仍需项目材料标定、网格收敛、完整工况和工程审查才能用于真实工程结论。
