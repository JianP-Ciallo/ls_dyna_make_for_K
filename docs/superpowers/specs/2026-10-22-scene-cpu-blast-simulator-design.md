# 基于现有五类建筑的 CPU 爆炸场景模拟器：产品目标修订

日期：2026-10-22（需求基线）。2026-10-23 用户授权开始实施，已接入实验场景工作台、候选宏单元内核和任务链路，见[实施与专项验证记录](../reports/2026-10-23-scene-cpu-blast-implementation.md)。以下“仍待开发”及“本次未改生产代码”等文字保留为 10 月 22 日设计时点的记录，不代表当前状态。随后用户明确授权的[首个三层 TNT 单例](../reports/2026-10-23-three-storey-first-tnt-trial.md)在初始自重平衡复核处失败，尚未施加爆炸荷载；技术精度与性能未验收，未运行其他真实工况。

本文件修正[此前小算例主导的设计](2026-10-22-fixed-building-cpu-response-design.md)的产品方向。原小算例、三层弹性首试和历史证据继续保留，作为内部验证与对照。用户体验以完整建筑场景为中心，不能再把单柱、单板列表作为 CPU 主界面，也不能用旧首试报告入口代替可编辑的场景模拟器。

2026-10-23 后续：[自重非线性平衡与诊断修复](../reports/2026-10-23-nonlinear-gravity-repair.md)已由微型算例和专项验证，未修改材料强度或跳过重力；三层整栋按用户要求等待再次确认重跑。

## 1. 用户已明确的需求

- 在现有模型上模拟：商超、住宅小区、地铁入口、城市街道、固定三层精细楼，共五类来源。用户已确认这一对应关系。
- 在三维场景中放置/移动单个 TNT，修改位置与当量后，点击一次“开始模拟”，由 CPU 计算整栋或城市场景的结构响应。
- 首版支持建筑外部、开阔城市场地；不要求首版支持室内、封闭空间爆炸。
- 首版必须包含开裂、构件失效或局部倒塌能力。只有弹性变形和应力、附带阈值着色，不满足这项要求。
- 希望单次计算在几十秒内完成，接受为此进一步简化结构。几十秒是目标，尚无实测承诺。
- 操作参考老师网站的场景流程，使用本项目自己的模型、代码、界面和视觉风格；保留既有建模和 K 导出能力。
- 前一轮已明确建筑预览与“压力与 K 文件”是“固定建筑压力分析”下的两个子页；本次设计不拆散它们。
- 当前仍不运行计算。全量、真实重型或慢模型生成仍按 AGENTS.md 的当次范围/耗时授权执行；本次需求确认不自动授权旧五例矩阵或新的真实场景。

## 2. 用户看到的统一流程

```mermaid
flowchart LR
  A[选择已有建筑或城市场景] --> B[三维拖放 TNT\n编辑 XYZ 与当量]
  B --> C[开始 CPU 模拟\n显示进度与停止按钮]
  C --> D[建筑响应回放\n变形、损伤与失效]
  D --> E[点选构件看曲线\n保存场景与结果]
  E --> B
```

建议布局：

```text
顶部：原统一导航 + 当前项目/保存状态
左侧：模型来源/当前模型 → TNT 坐标与当量 → 模拟设置 → 开始/停止
中央：始终显示选中的建筑场景、爆源与操作轴；结果在同一视窗回放
底部：播放/暂停、时间轴、速度、显示倍率
右侧或抽屉：选中构件信息、损伤/失效状态、峰值、真实响应曲线
结果菜单：历史场景、可恢复删除、下载输入快照/曲线/图片
```

拖动爆源时只更新输入和可视标记，不自动求解。修改模型或 TNT 后使旧结果失效，并保留原历史结果。开始后冻结模型、材料、爆源和数值设置快照；结果绑定这一快照。模型及未保存参数继续按项目隔离、在页面切换时保留。

主流程不要求用户先选择单柱/单板、不要求手填压力 CSV，也不要求先生成完整 LS-DYNA 空气域网格。每一次用户运行仍有独立记录，但这些记录属于同一个场景编辑/模拟流程，不作为产品功能的孤立算例卡片。

## 3. 五类模型共用显示与计算映射合同

| 来源 | 需要读取的现有信息 | CPU 适配重点 |
|---|---|---|
| 商超 | 资产几何、构件、结构体系与材料 | 大跨构件、支承、围护与主体的区分 |
| 住宅小区 | 多层住宅资产及当前项目参数 | 楼层、承重构件、填充墙、开口与质量 |
| 地铁入口 | 入口/通道几何与当前结构定义 | 地上/地下边界和承重墙；首版室外爆源不能冒充封闭通道传播求解 |
| 城市街道 | 已有城市布局、建筑实例与变换 | 各建筑承载关系和独立状态；城市传播能力及规模预算单列 |
| 固定三层精细楼 | 原 K/语义登记、配筋、当前规整参考 | 延续已核对的柱板承重、填充墙质量/传力政策，记录与原 K 的差异 |

显示模型继续采用现有外观；计算模型根据语义构件生成较少自由度的结构模型，二者通过稳定的实例/构件 ID 映射。简化必须保留质量、约束、主要承载路径和受载面，不采用给整个外观套统一位移动画的方法。

不同建筑按其真实登记的承重体系适配，不能把全部五类都硬转为同一种柱板体系。缺失材料/连接/配筋信息要记录参考假设及来源，不能从几何外观推断为已核验的实物参数。

## 4. 建议的首版物理路线（待验证）

### 4.1 从 TNT 工况计算荷载

采用有出处、可复核的室外经验爆炸荷载方法，依据爆源位置、当量、受载位置和表面朝向生成空间变化的压力时程，再传递到结构。每次移动 TNT 后重新计算这一荷载分布；不能继续使用同一条固定 10kPa 曲线假装支持任意爆源。

选用实现、来源/许可、适用域、到达时间、峰值、冲量与反射处理需要独立核对。经验表面荷载不能标成空气域压力场。城市中的遮挡、绕射、多次反射和街谷通道效应不能仅靠直线距离或可见性判断冒充已经求解；应明确标识所用近似、已验证范围和不支持的工况，不能把遮挡面静默设为零压力。

开始前检查 TNT 位于已支持的室外区域、没有嵌入构件且满足所选荷载方法适用域；不支持的室内、通道内部或传播条件明确拒绝/标记，不通过挪动图标绕过物理范围。

### 4.2 从荷载计算非线性结构响应

候选路线为构件级非线性简化模型：适合构件的梁柱/宏单元、粗化板墙或等效连接。复用现有 OpenSeesPy 的可用部分，但最终内核组合须以损伤、失效后稳定性及耗时验证决定，不能假定现有弹性三层求解器增加几个阈值即可完成。

建议必须保留：初始重力平衡；结构质量与惯性；非线性恢复力；与模型适配的混凝土开裂/压损、钢筋或钢构屈服；损伤后的刚度与承载力变化；连接状态与力的重新分配。材料/宏单元参数要有来源并与独立响应对照，损伤耗能与尺寸依赖应检查，不能靠任意破坏阈值取得所需画面。

### 4.3 损伤、失效和局部倒塌的边界

- **开裂**：建议先输出计算模型支持的开裂状态、位置/构件和损伤分布；是否绘制裂缝标记属于显示选择，不声称已经解出每条实际裂纹的路径和宽度。
- **构件失效**：由材料/构件承载退化和连接破坏规则产生，并真正改变后续受力。破坏规则和参数需要验证，不能由画面颜色或单一位移阈值决定。
- **局部倒塌**：必须处理失去支承后的重力、大位移和必要的简化接触；脱离部分的质量、动量及状态转移要一致。不能失效即删除质量，或切换成没有力学依据的坠落动画。
- **首版建议不追求的细节**：逐条裂纹扩展、任意碎片、爆炸气体流动、所有块体的精细碰撞及完整渐进倒塌。用户已接受简化结构，但这些显示/物理细节属于本方案建议的边界，尚不能写成用户逐项确认。

若候选内核只能支持开裂/失效而不能可靠处理局部坠落，则明确标记局部倒塌尚未实现；不能把整体变形或着色称为已经包含倒塌。也不能以此悄悄把用户要求重新降成纯弹性产品。

建议首版按已验证的破坏模式、允许坠落的构件集合及接触集合开放；具体集合在方法专项后确定并在开始前显示。有限范围的局部倒塌能力不能命名为任意建筑倒塌预测。

## 5. 数十秒目标及性能设计

先以约30–60秒作为候选目标区间，实际时间以具体硬件、五类模型规模和损伤复杂度的测试为准。既有真实三层弹性首试约97.95秒，且没有本次要求的非线性和坠落。因此现有内核的原尺度不是已证明可满足本目标的方案。

建议的性能措施：

1. 使用语义构件生成较少自由度的 CPU 模型，保留主承载路径；不直接求解原显示/实体/逐根钢筋的全部细网格。
2. 模型准备、可复用的稀疏结构及经验证的初始重力状态按输入身份缓存；改变 TNT 只重建相关荷载与运行状态，不复用上次的损伤或位移。
3. 在数值内核中逐步记录必要极值和损伤事件，曲线与动画分别控制输出密度；减少现有高成本逐钢筋采样点的逐步跨进程/接口提取。输出降采样不能丢失真实峰值或掩盖失稳。
4. 城市按已明确的构件与自由度预算运行。近远场差异化精度可以作为后续选项，不能在用户不知情时把城市其余建筑悄悄冻结或降低全部物理能力。
5. 先保证结果可回放；分块推送已提交帧可改善等待体验，但不能等同于已经实现实时求解。超时/失稳如实保留状态，不能自动放大步长、删除质量或忽略破坏来凑耗时。

每类模型应在真实运行前冻结可计算构件数、非线性自由度、接触规模和模拟时长的预算；具体数值需由方法/性能验证决定。本轮不随意写入未经测量的通用上限，也不对五类场景统一承诺相同耗时。

## 6. 后台验证和前台交付分开

后台仍需验证荷载、材料、构件、失效后受力和局部接触，这些检查不能被 UI 需求取代；但是验证不再充当用户使用产品的主界面。

建议交付围绕一条完整链路推进：先让真实模型和 TNT 编辑/快照贯通，再完成经过验证的荷载—结构损伤—结果回放链路，随后用同一合同适配五类模型。每个阶段都保留相同场景操作，不再交付一个个替代建筑场景的单构件页面。

用户验收应检查：

- 五类来源均可选择并显示对应的现有模型，模型/项目身份准确。
- 爆源坐标与当量可编辑；新输入与旧结果不会混用；一次“开始模拟”计算当前场景。
- 荷载与结构响应来自同一次计算，损伤/失效与后续运动一致；没有算出的现象不画成计算结果。
- 低于破坏条件时不会强制倒塌，损伤条件发生时也不会永远保持弹性；不同输入改变的是力学响应，不只是动画大小。
- 位移/应力/损伤的含义明确；选构件可看真实曲线，放大倍率不改变数值。
- 各来源的实际建模/求解/提取/加载耗时、适用规模和精度边界分别报告；数十秒目标是否达到据实判定。
- 原建模、两个固定建筑子页、K 导出、历史删除恢复和草稿保留不被破坏。旧 CPU 算例结果继续作为独立历史/开发验证资料，不转换成爆源计算结果。
