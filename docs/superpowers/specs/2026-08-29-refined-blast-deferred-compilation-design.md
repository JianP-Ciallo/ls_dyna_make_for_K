# 精细化建筑工作台延迟编译设计

## 目标

修复“保存草稿”触发完整精细化建筑编译、界面长期停留在“正在保存”、预览不可用，以及 TNT 位置因此无法在生成前持续修改的问题。

用户工作流必须变为：

1. 保存草稿只规范化并持久化建筑配置与工况配置，正常情况下数秒内完成。
2. 刷新预览只构造轻量几何代理，显示建筑包络、地面、可见空气域和当前 TNT 实体位置。
3. TNT 位置既可在三维预览中拖动，也可通过 X/Y/Z 数值字段修改；修改只使当前预览和既有生成物失效，不触发完整建筑编译。
4. 生成 K 包才执行完整精细化建筑编译，并且必须消费该项目最新持久化的 TNT 位置。

## 兼容策略

- 保留 `refined_blast_create@1` 的现有同步编译语义，确保旧客户端和已持久化项目继续工作。
- 新工作台改用 `refined_blast_create@2`。该版本创建项目时记录规范化建筑配方、建筑定义指纹和 `pending` 编译状态，不调用 `compile_detailed_building_asset`。
- 延迟项目首次生成时才产生真实 `BuildingArtifact`。编译成功后，在同一项目锁内把项目、元数据和创建事务中的建筑指纹物化为真实构件指纹，并将状态改为 `compiled`。
- 延迟项目前端响应显式公开 `building_compilation_state` 与 `building_definition_fingerprint`，不得把定义指纹描述为已编译网格证据。

## 后端请求路径

### 保存

`POST /projects`（`@2`）与 `POST /projects/{id}/save` 只执行：闭合字段校验、配方规范化、工况规范化、修订号冲突检查和原子 JSON 写入。它们不得调用详细建筑编译器。

### 轻量预览

延迟项目的 `POST /projects/{id}/preview` 从建筑资产描述的默认尺寸、项目覆盖参数和载荷提供器输入构造严格的九层预览：

- `structure`：建筑轴对齐包络代理；住宅场景按塔楼数量生成多个包络。
- `fluid_domain`：覆盖建筑平面范围并按空气域外扩量扩展的可见空气域代理。
- `blast_source`：使用当前持久化的爆源坐标和 TNT 当量估计的实体包络及位置标记。
- `support_ground`：与建筑足迹对应的地面代理。
- 其他层保持闭合契约和确定性空代理。

该预览明确标记为配置级、非求解器网格，计数使用上限语义，不作为最终单元数量证据。

### 验证

延迟项目在生成前执行配置级验证：校验修订号、提供器 ID、提供器输入闭合与数值规范化，并返回一条非阻断信息，说明完整网格/物理验证将在生成阶段执行。该验证允许用户进入生成，但不声称工程验证完成。

### 生成

`POST /projects/{id}/generate` 对延迟项目：

1. 在项目锁内确认请求修订号与最新持久化草稿一致。
2. 执行一次完整详细建筑编译。
3. 物化真实建筑工件指纹并缓存本次详细包。
4. 使用同一详细包和最新工况（包括 TNT X/Y/Z）生成 K 包。
5. 通过现有原子生成物提交路径推进项目修订号。

生成失败不得伪造成功证据；已经成功完成的建筑物化可以保留，以便同一进程内重试时避免无意义的重复编译。

## 前端行为

- 保存请求使用独立 `AbortController` 和 10 秒超时。成功、失败、超时或卸载都必须清理 busy 状态。
- 超时后保留相同项目 ID；重试依赖后端幂等创建事务，不创建重复项目。
- 卸载工作台时中止保存、预览、验证和恢复请求。
- TNT 三轴字段沿用同一 `charge_position_m` 草稿路径；预览拖动和数值输入都更新该路径并触发配置保存。
- “生成 K 包”只读取已经持久化的当前修订号；若仍有未保存修改，先完成快速保存。

## 验收标准

- 新协议创建与后续保存均不会调用完整建筑编译器。
- 新协议预览不调用完整建筑编译器，并包含建筑、空气域、地面和当前 TNT 坐标。
- 生成阶段调用完整建筑编译器，并将最新 TNT 坐标写入生成清单。
- 保存请求无响应时 10 秒内退出 busy 状态并显示可重试错误；卸载会中止请求。
- 旧 `@1` API 测试与现有 Phase18F 兼容测试继续通过。
