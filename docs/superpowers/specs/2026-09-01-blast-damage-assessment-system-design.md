# 爆炸后建筑与地面损伤评估系统阶段性设计方案

> 状态：详细设计已完成，等待实施计划确认。
>
> 日期：2026-09-01

## 1. 建设顺序

项目后续按两个阶段推进：

1. 第一阶段建设爆炸后建筑与地面损伤评估系统。
2. 第二阶段在稳定评估系统之上进行智能体化，引入 DeepSeek API，对整体爆炸效果、建筑损伤和地面损伤进行综合分析与交互解释。

第一阶段不依赖大模型。工程指标、损伤等级和证据均由确定性评估程序产生。第二阶段的 DeepSeek 不得替代或修改第一阶段的工程判定。

## 2. 第一阶段目标

第一阶段只评估数值仿真完成后的结果，面向当前快速建模项目生成的 LS-DYNA 模型，输出建筑与地面的分区/构件级损伤结论及相应报告。

报告定位为研究与工程辅助决策材料，不作为无需复核即可使用的正式工程鉴定结论。报告必须展示数据来源、判定依据、不确定性和人工复核提示。

## 3. 已确认的范围与边界

### 3.1 输入范围

- 第一版只接收已经完成的数值仿真结果。
- 第一版不负责启动、监控或终止 LS-DYNA 求解器。
- 第一版只保证评估由当前快速建模项目生成的模型。
- 系统利用当前项目已有的建筑、构件、地面、Part 和区域语义关系。
- 外部 LS-DYNA 模型和其他求解器不在第一版支持范围内，但标准数据接口需允许未来增加适配器。

### 3.2 评估对象

- 建筑：墙、柱、梁、楼板、屋面及建筑空间分区等对象。
- 地面：爆坑、隆起、沉降、塑性破坏及其影响范围等对象。

### 3.3 结果粒度

- 建筑和地面分别使用符合各自破坏机理的指标及规则。
- 输出分区级、构件级和对象级的局部结论。
- 最终统一汇总为五级严重度：无明显、轻微、中等、严重、极严重。

## 4. 选定的总体路线

采用“标准化数据驱动的模块化评估系统”，不把结果解析、损伤规则和报告逻辑直接耦合到现有建模流程中。

总体数据流为：

```text
当前项目模型语义 + 已完成的 LS-DYNA 结果
    -> LS-DYNA 结果适配器
    -> 标准评估数据
    -> 数据质量门禁
    -> 建筑评估器 / 地面评估器
    -> 五级严重度汇总
    -> 证据包与损伤报告
```

该路线的目标是隔离变化：当前建模项目继续优化时，通过稳定的模型语义清单与评估系统交互；LS-DYNA 结果格式发生变化时，只调整适配器；规则发生变化时，只增加或升级规则包。

## 5. 系统模块

### 5.1 评估入口

接收项目编号、模型清单、构件语义清单、结果目录和选用的规则版本。入口只创建评估任务，不承担求解器调度。

### 5.2 LS-DYNA 结果适配器

读取当前项目产生的结果，将 Part、单元、建筑构件、建筑区域和地面区域关联起来，并将评估所需数据转换为统一格式。适配器不得直接作出损伤等级判断。

### 5.3 标准评估数据层

保存单位、时间、位置、对象身份、响应指标、质量状态、评估结果和证据引用。标准数据格式独立于 LS-DYNA，并带有明确的模式版本。

### 5.4 数据质量门禁

在正式评级前检查：

- 结果文件和关键字段是否完整；
- 单位、坐标系和时间定义是否一致；
- 求解是否正常结束；
- 建筑、构件、地面和 Part 身份是否可追踪；
- 关键指标是否缺失或明显异常。

门禁输出以下三级结论：

1. formal（可正式评级）：材料、单位、求解状态、对象身份和必要结果字段均满足所选规则要求，允许输出五级损伤等级；
2. provisional（仅限预评估）：结果数据完整，但材料或工程标定尚未满足正式评级条件，只能输出五级响应严重度，并显著标记为不可替代工程损伤鉴定；
3. blocked（不可评估）：关键结果、单位或对象身份缺失，只输出问题清单、已获得的数据和建议复核项，不输出等级。

非关键数据缺失时可以降级运行，但必须在结果中记录缺失字段、受影响指标和降级原因。当前项目使用的初步材料预设默认进入 provisional，不能因求解正常结束而自动提升为 formal。

### 5.5 确定性评估核心

建筑评估器和地面评估器独立工作。两者分别完成指标提取、阈值比较、局部评级和证据生成，再由汇总器产生统一五级严重度。

评估采用“默认工程规则 + 项目可配置阈值”的方式：

- 系统提供经过验证的默认规则；
- 用户可以按规范、试验或具体项目要求建立规则配置；
- 每个规则包拥有唯一标识和版本；
- 每次评估记录实际使用的规则快照；
- 修改规则不得覆盖历史评估所依赖的规则版本。

#### 5.5.1 建筑首版评估策略

建筑采用“构件分类 + 多指标”方式评估。每个评估对象先按其对结构稳定性的作用划分为 primary（主要结构）、secondary（次要结构）或 nonstructural（非结构），再使用与构件类型相符的指标和规则。

重要性分类优先来自主项目模型语义清单中的显式 importance_class。旧模型缺少该字段时，适配器可以依据构件角色和规则包进行安全回退；只要存在推断分类，门禁最高只能输出 provisional，报告必须列出推断依据和待确认对象。关键构件无法可靠分类时输出 blocked。

首版建筑指标包括：

- 变形响应：峰值位移、残余位移、跨中挠度比、支座转角和可计算时的层间位移角；
- 材料响应：应力利用率、等效塑性应变和材料模型明确提供的损伤变量；
- 失效响应：删除单元比例、连续失效区域及关键位置失效；
- 影响范围：超限单元比例、超限面积或体积以及最大连续受损区域；
- 功能后果：承重路径受损、围护破坏和构件可修复性提示。

单构件采用“关键失效触发 + 多指标稳健统计”：普通响应同时记录峰值、残余值、P95/P99、超限比例和连续受损区域，不允许仅凭全构件平均值或孤立单元最大值决定等级；关键位置失效、连续单元删除或承重路径中断可以触发等级提升。孤立数值尖峰先作为异常证据，只有获得相邻单元、其他指标或时间连续性的支持后才参与正式评级。

所有数值阈值均属于版本化规则包。来源于单自由度或特定试验方法的限值必须记录适用条件，不得在不满足分析假设时直接宣称为等价工程判定。

建筑专业判据由评估系统维护，普通用户不需要自行填写专业阈值。首版提供 building_research_reference@1 研究参考规则包，并预留 building_project_calibrated@1 项目标定规则包。研究参考规则包依据 USACE PDC-TR 06-08（2025）、UFC 4-010-01 及当前模型可验证的材料元数据建立，只能产生 provisional 结果；项目规则包只有在材料、构件参数、适用条件、来源和复核记录完整时才能产生 formal 结果。

材料字段必须按实际材料卡解释：K&C 混凝土在当前 NOUT=2 配置下输出的是缩放损伤量，不能冒充普通等效塑性应变；弹塑性钢材的塑性应变只能与对应钢材的标定参数比较；弹性材料不具备塑性破坏判定能力，零塑性应变不能解释为无损伤；当前侵蚀卡的删除事件只作为数值删除证据，不能单独证明物理断裂。

统一五级显示语义为：0 无明显，1 轻微且局部可修复，2 中等且需要明显修复或存在广泛次要损伤，3 严重且构件不可修复或主要承重路径受到威胁，4 极严重且存在主要构件失效、坍塌、渐进倒塌或危险抛射证据。规则包必须保留原始标准的损伤术语和映射依据，不能只保存转换后的中文等级。

#### 5.5.2 地面首版评估策略

地面采用“爆心种子 + 连续区域 + 径向分析”方式评估。适配器从模型语义获得爆心地面投影、竖向轴和初始地表，评估器以爆心邻域为种子识别连续凹陷、隆起和材料破坏区域，并按距爆心的环带输出响应衰减。远离爆心的孤立异常不并入爆坑，连续区域的最小网格规模由规则包控制。

首版地面指标包括爆坑最大深度、面积、等效直径和体积，隆起最大高度、面积和体积，坑外最大沉降及影响面积，塑性应变或材料损伤区，以及删除单元数量和侵蚀体积。材料模型不支持的指标必须标记为不可用，不能用零值代替。

地面结果区分峰值响应、末时刻瞬时形态和残余形态。峰值响应始终可以在字段完整时计算；只有末段多个时间步的地表垂向速度、爆坑几何、隆起和沉降范围均达到规则包定义的稳定条件，才允许把末态称为残余爆坑或最终沉降。时间帧不足或响应未稳定时，只输出瞬时形态并建议延长求解时间。

爆坑、隆起、沉降、塑性破坏和单元侵蚀分别评级。地面总体等级由最严重的可信分项控制，同时完整保留各分项等级和证据；不可用或可信度不足的分项不参与总体等级，但必须进入问题清单。当前诊断性弹性土体最多输出 provisional 地面响应严重度。

#### 5.5.3 总体汇总与冲突处理

建筑和地面始终保留两个独立等级及其门禁状态。只有两部分都至少达到可预评估条件时才生成总体等级，总体等级由最严重的可信分项控制，不进行加权平均。任一部分为 provisional 时总体最多为 provisional；任一部分为 blocked 时总体等级留空并标记为部分评估，禁止把缺失结果当作零损伤。

建筑内部保留主要结构、次要结构和非结构三类等级。主要结构的关键失效可以直接触发高等级；次要或非结构构件只有在形成危险抛射、广泛失效、阻断疏散或与主要结构损伤形成证据链时才触发同等级的整体后果。不同指标冲突时保留全部指标和规则命中记录，采用可解释的保守结果，并生成复核项。

### 5.6 证据与报告模块

每条损伤结论必须形成以下证据链：

```text
原始结果位置 -> 对象身份 -> 提取值 -> 计算指标 -> 规则及阈值 -> 局部等级 -> 汇总等级
```

报告应至少包括算例摘要、数据质量说明、建筑损伤、地面损伤、五级汇总、关键证据、不确定性、异常项和人工复核建议。

### 5.7 模块化边界与主项目接口

评估系统建设为可独立安装、测试和验收的 Python 模块。主项目不得直接调用 LS-DYNA 二进制解析器、损伤规则或报告生成器的内部实现，只能通过评估系统公开接口提交任务、查询能力并读取不可变评估快照。

首版同时提供两个入口：

1. Python API：blast_damage_assessment.api.assess(request)；
2. JSON/命令行接口：python -m blast_damage_assessment evaluate --request <request.json>。

两个入口使用同一套版本化请求与结果模式。Python API 供同一运行环境中的主项目调用；JSON/命令行接口用于独立验收、隔离部署和故障排查。首版只处理已经完成的结果，因此采用同步调用，不承担 LS-DYNA 求解调度。

请求模式 blast_damage.assessment_request@1 至少包含：

- 项目与工况标识；
- 只读结果目录；
- 模型语义清单或其受验证引用；
- 规则包标识与版本；
- 独立的评估输出目录。

结果模式 blast_damage.assessment_result@1 至少返回：

- 评估任务标识和执行状态；
- formal、provisional 或 blocked 门禁结论；
- 标准评估快照、证据索引和报告的路径及摘要哈希；
- 警告、阻断问题和人工复核项；
- 实际使用的适配器、模式和规则版本。

评估系统不得修改原始模型和求解结果。所有产物写入请求指定的独立输出目录，并使用临时文件加原子替换生成最终文件。主项目后续只增加一个薄桥接层，负责从已有结果源与证据记录构造评估请求，并把评估结果登记回主项目；桥接层不得复制评估算法。

LASSO 仅封装在 LS-DYNA d3plot 读取器内部。评估系统先把 LASSO 返回值转换为标准评估数据，再交给门禁与评估器；公共接口和确定性规则均不得暴露 LASSO 类型。

## 6. 标准评估数据内容

标准数据层至少包含以下信息类别：

- 算例信息：项目、模型、工况、求解时间、坐标系和单位制。
- 对象索引：建筑、楼层、空间分区、构件、地面区域及其与 Part/单元的对应关系。
- 响应数据：各对象的峰值、残余值、时程摘要、极值时间和空间位置。
- 质量状态：完整性、求解状态、单位检查、异常值、缺失项和降级原因。
- 评估结果：指标、局部等级、总体等级、置信状态和复核项。
- 证据引用：原始文件、对象编号、时间步、规则编号及计算摘要。

标准数据不以复制全部 LS-DYNA 原始结果为目标，只保存评估、复核和复现所必需的信息。

### 6.1 首版输入文件与字段

首版请求必须提供只读结果目录、模型语义清单的受验证引用、规则包和独立输出目录。结果目录必须包含 model.k、model.json、run.json、d3hsp 以及从 d3plot 开始且编号连续的二进制结果系列。模型清单可以位于结果目录之外，但请求必须记录其路径和哈希；缺少可信对象到 Part/单元映射时，只阻断受影响的建筑或地面子评估。

求解质量必须能够由受验证的 run.json 求解评估记录，或由 d3hsp、glstat、matsum 重新计算。既没有可信记录也没有足够原始文件时输出 blocked。dbfsi、nodout 和 elout 作为补充证据；缺少补充文件不自动阻断，但依赖这些文件的指标不可用。

LASSO 读取器必须获得时间步、节点编号、初始坐标、变形后节点位置、Part 编号与标题、单元编号、单元连接和单元到 Part 的关系。节点速度用于残余状态稳定性判断；缺少速度时仍可计算瞬时几何，但不得声明残余状态。实体、壳和梁的应力、损伤量、塑性应变及存活状态按材料能力逐项启用，某一族字段缺失只降级依赖该字段的指标。

LASSO 2.0.4 返回的 node_displacement 在当前结果中按变形后坐标解释，适配器必须以其减去初始坐标生成物理位移，并通过初始帧回零测试防止语义回归。K&C NOUT=2 字段按缩放损伤量保存，不统一改名为普通塑性应变。

### 6.2 首版输出产物

每次评估在独立目录中生成：

- assessment_request.json：规范化后的请求快照；
- assessment_result.json：供主项目和命令行读取的结果信封；
- assessment_snapshot.json：完整标准评估数据；
- evidence_index.json：原始文件、哈希、对象、时间步和规则命中的证据索引；
- rule_snapshot.json：本次实际使用且不可变的规则快照；
- damage_report.html：可离线打开的自包含中文损伤报告；
- building_components.csv：建筑构件指标、等级和门禁状态明细；
- ground_regions.csv：爆坑、隆起、沉降和材料破坏区域明细。

JSON 使用 UTF-8，CSV 使用带签名 UTF-8 以兼容常用表格软件。HTML 不依赖网络资源，并突出显示 formal、provisional 或 blocked。首版不把 PDF 作为硬依赖，后续从同一评估快照增加导出器。

### 6.3 处理规模约束

适配器按时间步分块处理大体积 d3plot，只保留指标累计量、必要峰值帧和证据定位，不在标准数据层复制完整求解数组。块大小属于运行配置但不影响结果语义；改变块大小必须得到相同指标和等级。

## 7. 兼容与可追溯约束

1. 标准数据格式和规则包分别版本化。
2. 原始值与标准单位值同时保留，所有换算均可追踪。
3. 当前项目通过稳定的模型语义清单提供身份关系，不依赖评估模块内部结构。
4. 适配器、评估器、规则包和报告生成器通过明确接口隔离。
5. 新字段采用向后兼容方式增加；旧数据缺少非关键字段时允许带警告降级。
6. 缺少关键身份、关键结果或必要单位信息时禁止输出正式等级。
7. 每次评估生成不可变快照，使相同输入与相同规则能够复现相同结果。
8. 公共请求和结果模式按主版本兼容；同一主版本只新增可选字段，改变必填字段或既有语义时发布新主版本。
9. 遇到不支持的接口主版本时必须拒绝执行，不能猜测字段或静默降级。
10. 评估模块提供能力查询接口，使主项目可在调用前确认适配器、模式版本和规则包是否可用。

## 8. 第二阶段 DeepSeek 接入边界

第二阶段通过 API 连接 DeepSeek。DeepSeek 只读取第一阶段输出的结构化评估快照和证据摘要，用于：

- 综合解释建筑与地面的整体爆炸效果；
- 总结主要损伤区域和关键构件；
- 回答用户关于评估结果的问题；
- 生成面向不同读者的报告说明。

DeepSeek 不直接解析 LS-DYNA 原始结果，不执行数值求解，不改变损伤等级，不覆盖工程规则，也不能绕过数据质量门禁。

## 9. 首版验收标准

1. 评估包能够在独立环境安装和运行，核心模块不导入主项目内部实现。
2. Python API 与 JSON/命令行入口对同一请求产生相同评估指纹、门禁状态、指标和等级。
3. 商业、住宅和地铁三类现有完整结果均能解析，节点数、单元数、Part 身份和最终时间与 run.json、模型清单及 d3hsp 一致。
4. 三类现有结果因材料尚未工程标定必须输出 provisional；任何 formal 结果均视为验收失败。
5. 当前缺少的实体/壳应变和梁应力字段必须表现为明确的指标不可用或变形指标降级，不能写成零响应。
6. 缺失或断裂的 d3plot 系列、未达到终止时间、异常终止、单位缺失、对象身份断裂、证据哈希变化和不支持的接口主版本均有负面测试并按规则阻断。
7. 地面响应未稳定时可以输出峰值和末态瞬时形态，但不得输出残余爆坑或最终沉降。
8. 相同输入证据和规则快照重复运行必须得到相同评估指纹及确定性数据内容；处理块大小不得改变结论。
9. 评估前后原始模型和求解结果的文件哈希保持不变，所有写入限制在独立输出目录。
10. 每个建筑构件等级、地面分项等级和总体等级都能沿证据索引追溯到原始文件、对象、时间步、指标和规则。
11. 在当前开发机上，任一完整基准算例应在五分钟内完成且峰值常驻内存不超过 2 GiB；超限即进入性能整改。
12. HTML 报告可离线打开，CSV 可由常用表格软件正确显示中文，并与 JSON 快照中的对象数量和等级一致。

## 10. 实施入口

详细设计确认后，先编写逐文件、逐测试的实施计划，再通过独立 Git 工作树建设评估包。独立包通过上述验收前，不修改主项目调用流程；通过后再单独实施主项目薄桥接层。第二阶段 DeepSeek 接入不属于首版评估系统实施范围。
