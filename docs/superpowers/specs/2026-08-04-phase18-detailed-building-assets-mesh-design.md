# Phase 18 建筑类旧资产精细化版本与网格规范设计

日期：2026-08-04
状态：原 RC 资产与参考网格设计；已被多结构体系方案扩展

> **重构说明（2026-08-05）：** 本文的 RC 配筋与 `coarse/standard/fine` 数值继续作为 `rc_reference_profile`，但“所有建筑都生成钢筋混凝土版本”已不再是正式路线。多结构体系、真实空腔和独立工况的现行设计见 `docs/superpowers/specs/2026-08-05-phase18c-f-multi-system-refined-building-blast-redesign.md`。

## 1. 决策摘要

Phase 18 的精细化资产范围从单一商业超市扩大为现有模型库中的全部建筑类资产。首批固定覆盖：

- `commercial_supermarket`：商业超市；
- `residential_community`：住宅社区；
- `subway_entrance`：作为建筑结构处理的地铁入口。

车辆、停车场、交通灯以及板、杆、圆柱、壳体等通用或非建筑组件不在本次精细化资产范围内。

旧建筑资产不原地修改。每个旧资产保留现有轻量版本，同时增加独立的钢筋混凝土精细版本。精细版本由 Phase 18C 内核根据结构语义重新生成混凝土 Solid、钢筋 Beam、材料、截面、集合和耦合关系，不把旧壳网格直接拉伸为实体，也不从旧网格猜测配筋。

## 2. 资产版本与兼容边界

每个建筑资产使用一个稳定的资产族标识，并至少包含两个互不替代的变体：

```text
building asset family
├─ legacy_light
│  └─ 既有几何、生成器、ID 及默认调用行为
└─ detailed_rc
   ├─ 参数化结构语义
   ├─ 八节点混凝土 Solid
   ├─ 钢筋 Beam 与 N3 方向节点
   ├─ Part/Section/Material 映射
   ├─ 钢筋—混凝土嵌入集合
   └─ 独立版本、网格清单与验证状态
```

兼容规则：

1. 未显式选择 `detailed_rc` 时继续使用旧版本，旧项目输出不得改变。
2. 精细版本使用独立资源 ID、目录、schema 版本、有限元 ID 空间和 `fidelity_fingerprint`。
3. 两个版本可以共享名称、分类和几何来源关系，但不得共享求解结果、网格指纹或验证结论。
4. 精细版本发生结构、配筋、材料或网格变化时生成新版本，不覆盖旧版本。
5. 新增建筑类旧资产不会自动取得精细版本；必须通过同一资产审核和验收流程显式登记。

## 3. 建筑语义重建

旧资产仅提供显示语义、外轮廓和已有尺寸候选。精细版本必须显式补足以下结构信息：

- 建筑平面尺寸、轴网、层数、层高和屋面形式；
- 柱网、梁截面、楼板厚度、墙体厚度、基础形式和可选剪力墙；
- 梁柱纵筋、箍筋、板筋、墙筋和基础钢筋；
- 钢筋直径、数量、间距、保护层、加密区、锚固和搭接简化规则；
- 构件连接方式、边界集合、外表面集合及嵌入耦合关系；
- 审核后的混凝土和钢筋材料资源。

任何不能由旧资产可靠推导的结构参数都必须使用经审核的资产默认值或用户输入，不能根据旧壳单元拓扑静默猜测。

## 4. 已确认的初始网格规范

### 4.1 实体网格预设

Phase 18C 使用八节点六面体 Solid 作为程序化实体内核的目标单元。初始网格预设为：

| 预设 | 梁/柱/基础名义尺寸 | 楼板/墙体名义尺寸 | 厚度方向最少单元层数 | 用途 |
| --- | ---: | ---: | ---: | --- |
| `coarse` | 0.150 m | 0.0750 m | 2 | 快速预览、流程验证和规模估算 |
| `standard` | 0.100 m | 0.0500 m | 3 | 默认精细化建筑模型 |
| `fine` | 0.075 m | 0.0375 m | 4 | 网格敏感性研究候选 |

构件的实际网格尺寸必须同时满足名义尺寸和厚度分层约束：

```text
resolved_solid_size = min(
    component_nominal_size,
    component_thickness / minimum_thickness_layers
)
```

每个几何方向使用向上取整后的单元数重新计算实际尺寸，避免末端产生极小残余单元。相邻构件采用共节点或经审核的显式连接策略；不能通过重叠实体掩盖网格不匹配。

### 4.2 钢筋离散

钢筋 Beam 使用与实体网格协调但独立的离散参数：

| 预设 | 普通区最大 Beam 长度 | 加密区目标 Beam 长度 |
| --- | ---: | ---: |
| `coarse` | 0.150 m | 0.0750 m |
| `standard` | 0.100 m | 0.0500 m |
| `fine` | 0.075 m | 0.0375 m |

钢筋直径和配筋间距不直接替代 Beam 离散长度。生成器必须分别记录几何配筋参数和有限元离散参数，并验证 N3 方向节点、零长度单元、重复单元及保护层范围。

### 4.3 `2.k` 参考依据与限制

拆分资源的直接统计表明：梁、柱和基础的十节点四面体角点边长中位数约为 0.10 m，楼板约为 0.05 m；钢筋 Beam 长度主要分布在 0.05–0.10 m。因此 `standard` 预设以这两个实体特征尺度为初始参考。

`2.k` 使用十节点四面体，而 Phase 18C 目标为八节点六面体。同一名义边长不代表相同自由度、数值耗散或精度。上述数值是初始建模规范，不是工程收敛结论；工程精度仍需真实求解、网格敏感性和试验或文献证据。

## 5. 用户覆盖与规模门禁

设计窗口必须允许用户：

- 选择 `coarse`、`standard` 或 `fine`；
- 覆盖单个构件类别的名义网格尺寸；
- 设置受控局部细化区域；
- 独立设置普通区和加密区钢筋 Beam 长度；
- 查看解析后的实际尺寸、厚度层数和粗细过渡；
- 在正式生成前查看节点、Solid、Beam、内存和输出文件规模估算。

任何覆盖值必须为正有限数，并满足项目配置的最小尺寸、最大尺寸、厚度层数、粗细过渡和总规模限制。超过软预算时要求用户确认；超过硬上限时阻断生成。所有确认和值解析结果进入项目来源记录和 `mesh_manifest`。

## 6. 数据流与输出

```text
旧建筑资产语义
  -> detailed_rc 结构参数
  -> 网格预设与构件覆盖
  -> 厚度分层和规模预检
  -> Phase 18C Solid/Beam 生成
  -> 材料、截面、集合与耦合装配
  -> 静态质量检查
  -> 精细建筑资产版本
  -> refined_building_blast 场景显式选择
```

每个精细资产至少输出：

- `geometry_manifest`；
- `mesh_manifest`，包括预设、请求尺寸、实际尺寸、厚度层数和规模；
- `reinforcement_manifest`；
- `part_material_section_map`；
- `embedded_coupling_sets`；
- `fsi_exterior_segment_set`；
- `boundary_sets`；
- `fidelity_profile` 与 `fidelity_fingerprint`；
- 旧资产来源关系、资源版本和审核状态。

## 7. 错误与警告策略

以下情况必须阻断生成：

- 缺少必要结构语义或配筋定义；
- 网格尺寸非正、非有限或超过硬限制；
- 厚度方向无法满足最少单元层数；
- 相邻构件存在未经声明的间隙、重叠或重复 Solid；
- 钢筋越出保护层、悬空、重复或错误跨构件嵌入；
- Part、Section、Material、Set 或 Coupling 引用不闭合；
- 预计规模超过硬预算。

以下情况可以生成研究模型，但必须记录警告并保持 `requires_project_review=true`：

- 使用尚未工程标定的材料参考卡；
- 使用 `coarse` 预设进行响应研究；
- 未完成真实前处理器导入或求解验证；
- 未完成当前建筑类型的网格敏感性研究。

## 8. 验收与测试

Phase 18D 扩大后的验收至少包括：

1. 商业超市、住宅社区和地铁入口都能生成独立 `detailed_rc` 资产。
2. 每个资产都同时包含混凝土 Solid、钢筋 Beam、N3 节点和嵌入集合。
3. 三档网格预设解析稳定，同一输入生成相同 ID、清单和指纹。
4. `standard` 预设解析为梁/柱/基础 0.10 m、板/墙 0.05 m，并执行不少于三层的厚度约束。
5. 单构件覆盖只重划分受影响构件，同时使旧预览和旧结果失效。
6. 规模预估与生成后的节点、Solid 和 Beam 统计一致。
7. 旧资产及不带 `detailed_rc` 选择的既有输入保持原有输出。
8. 每个资产通过引用闭包、ID 唯一性、实体质量、钢筋保护层和外表面集合检查。
9. 静态检查通过不等同于工程精度；外部导入、真实求解和收敛证据分别记录。
