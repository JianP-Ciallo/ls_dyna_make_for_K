# MM-ALE 受控场景归类设计

## 目标

只将“MM-ALE 爆炸”从顶层“建模模式”移入“受控场景”的场景选择器。参数化通道爆炸、K&C 柱形埋置装药和自由装配的导航归属保持不变。

## 范围

- 顶层模式不再提供 `ale_blast`。
- 受控场景选择器增加 `ale_blast`，显示名称为“MM-ALE 爆炸”。
- 选择该场景时显示现有 `aleBlastPanel`，隐藏普通受控场景的需求描述和动态字段。
- 继续使用现有 `/api/ale-blast/validate` 和 `/api/ale-blast/generate` 接口。
- 不修改 MM-ALE 模型参数、关键字生成、LS-DYNA 启动或结果验收逻辑。

## 界面行为

顶层“建模模式”保留：

- 受控场景
- 自由装配
- 参数化通道爆炸
- K&C 柱形埋置装药

当顶层模式为“受控场景”且场景模板为“MM-ALE 爆炸”时：

- 场景模板选择器保持可见，用户可以切回其他受控场景。
- 普通受控场景字段隐藏。
- MM-ALE 专用参数面板显示。
- 检查、生成、确认摘要和默认项目名继续走现有 MM-ALE 分支。

## 风险说明

MM-ALE 面板必须明确说明：

- “受控”表示输入模式和服务端生成路径受控，不表示工程结果已验证。
- 当前场景是 Phase 14 软件验证参考场景，只生成求解草案。
- Composition B 参数是参考数据。
- 钢板周边完全固定。
- 网格收敛性尚未证明。
- 真实求解仍需显式批准。

## 兼容性

后端工具名、HTTP 路由、请求载荷和项目模型格式保持不变。已有 MM-ALE 项目不需要迁移；只改变浏览器界面的入口位置。

## 验收

- HTML 中 `modelMode` 不含 `ale_blast` 顶层选项。
- JavaScript 将 `ale_blast` 添加到受控场景选择器。
- MM-ALE 模式判定同时要求顶层模式为 `controlled` 且场景为 `ale_blast`。
- 选择 MM-ALE 后，场景选择器仍可见，普通受控字段隐藏，MM-ALE 面板显示。
- 风险说明在 MM-ALE 面板和生成确认摘要中可见。
- 现有 MM-ALE API 路由保持不变。
