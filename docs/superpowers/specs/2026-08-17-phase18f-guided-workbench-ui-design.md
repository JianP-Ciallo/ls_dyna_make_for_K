# Phase 18F 引导式精细化工作台界面优化设计

日期：2026-08-17  
状态：已确认设计方向，待书面复核  
范围：`/refined-building-blast` 独立工作台前端；不改变 Phase 18E 生成语义、公开 API 或旧工作台

## 1. 背景与目标

当前精细化建筑爆炸工作台同时常驻八步导航、三维预览、九个图层开关、完整 schema 表单、即时检查、预算确认和五个底部动作。功能已经可用，但主次不清、右侧字段密集、对象字段以 JSON 文本呈现，导致宽屏仍显拥挤。

本次优化采用“A：引导式画布”：三维预览保持视觉中心，左侧导航压缩成步骤轨道，右侧只显示当前步骤或当前检查上下文。目标是降低一次可见的信息量，不删除任何能力，也不把安全门隐藏成默认成功。

成功标准：

- 初次进入时能立即识别当前步骤、三维预览、保存状态和下一项可执行动作。
- 默认界面不显示整段 `budgets`、`load`、`selection`、`source` JSON。
- 爆源位置可以通过 X/Y/Z 数值、三维点选和三轴拖动修改。
- 保存、预览、校验、确认、生成和外部程序授权语义保持不变。
- 旧工作台、城市编辑器、Phase 17 路由和旧 WebGL 状态不受影响。

## 2. 页面信息架构

### 2.1 顶部状态栏

顶部高度收紧，保留页面标题和“返回原工作台”。标题右侧显示项目状态摘要：项目名或 ID、服务端 revision、保存状态和检查状态。工程边界说明缩短为一行辅助文字，不与主标题争夺视觉注意。

### 2.2 左侧步骤轨道

八项配置导航改为窄步骤轨道。每项显示编号、短标题和状态：当前、已配置、警告或错误。默认只显示短标题；悬停、键盘聚焦或选中时展示完整说明。

点击步骤只切换右侧上下文，不修改 `ScenarioDraft`。步骤与现有八类能力一一对应，保持 schema 驱动的不适用项隐藏规则。

### 2.3 中央三维画布

中央画布占据最大空间。相机操作收为紧凑工具组。九个图层不再纵向平铺，改为画布左下方“图层 9/9”入口；展开后用紧凑网格显示图层开关，并保留独立可访问标签。

规模摘要改为画布底部状态带：默认只显示节点、单元、表面和预算状态等核心指标，展开后查看全部八类 exact/upper-bound 计数。

### 2.4 右侧上下文检查器

右侧宽度固定在适合表单阅读的范围，顶部提供“配置”和“检查”两个标签：

- “配置”只显示当前步骤适用字段。
- “检查”显示当前 revision 的错误、警告、预算和确认状态。

错误仍可跳转到对应步骤和字段。窄屏下检查器变为右侧抽屉；移动宽度下变为画布下方的全宽面板。

### 2.5 底部操作区

底部动作区从五等分大按钮改为紧凑状态栏：

- 左侧显示“保存中 / 已保存 / 保存失败”。
- 中部保留“保存草稿”“刷新预览”。
- 右侧根据服务器门禁显示“验证”或“生成 K 包”。
- “打开 LS-PrePost”和“启动 LS-DYNA”收进“外部操作”菜单。

外部操作仍默认禁用；必须存在当前 revision 的已验证生成包并逐次确认，不能因收进菜单而绕过身份、nonce、snapshot 或授权检查。

## 3. Schema 表单与高级参数

表单继续消费服务端发布的闭合 schema，不建立第二套业务默认值。

默认渲染规则：

- 数值：带单位、范围和步长的数字输入。
- 三维向量：X/Y/Z 三个并列数字输入。
- 枚举：下拉选择。
- 布尔：开关。
- 字符串数组：标签或多选列表。
- 嵌套对象：语义分组卡片或折叠段落。

`budgets`、`load`、`selection`、`source` 等对象默认以语义字段呈现。原始 JSON 只保留在“高级参数”折叠区，默认关闭；展开时明确标记为专家编辑。折叠不删除值，切换 provider 或 asset 时仍由现有 schema 规范化逻辑清理不适用旧值。

如果某个闭合 schema 类型尚无专用控件，只允许在高级区使用受 schema 校验的结构化编辑器，不能退回无约束文本保存。

## 4. 爆源位置编辑

### 4.1 数据真源

爆源位置始终写入现有 provider 输入：

- `lbe_segment`：`load_provider.provider_input.source.position_m`
- `explicit_ale_fsi`：`load_provider.provider_input.charge.position_m`
- 不使用爆源坐标的 provider 不显示该控件。

不存在独立的前端“视觉位置”副本；XYZ 输入、点选和拖动最终都更新同一个 `ScenarioDraft` 路径。

### 4.2 数值输入

“爆源与载荷”步骤提供 X、Y、Z 三个米制输入。有限数检查在本地立即执行；空间归属、实体穿入、域范围和工况合法性仍由 Phase 18E 权威验证决定。

### 4.3 三维点选与拖动

用户点击“在视图中放置爆源”后，可在已渲染几何上选取初始点。选中标记显示 X/Y/Z 三轴操纵器：

- 拖动时只更新本地预览和坐标读数。
- 指针释放或键盘确认时，单次提交到 `ScenarioDraft`，避免拖动每一帧触发自动保存。
- Esc 取消本次拖动并恢复起始坐标。
- 数字输入始终可完成同等操作，保证键盘可访问性。

界面不静默吸附或篡改坐标。未验证位置用等待色，权威验证判定非法后标记变红、显示原因并保持生成禁用；合法位置使用正常爆源色。

点选只负责得到初始空间点，三轴操纵器和 XYZ 数值负责精确调整。所有视图事件必须绑定当前 mount、project、draft revision 和 viewer 实例，迟到事件不能修改已切换的项目。

## 5. 状态与数据流

新增的界面状态仅包括当前步骤、检查器标签、展开的高级组、图层弹层和进行中的爆源拖动。它们属于单次 mount 的视图状态，不写入项目业务数据。

业务数据流保持：

1. 用户编辑 schema 字段或确认爆源坐标。
2. 现有 store 规范化并递增 `draft_revision`。
3. 旧预览、validation、acknowledgement 和 generation gate 失效。
4. 自动保存仍使用同一 single-flight/CAS 流程。
5. 预览、验证和生成仍携带服务端 `expected_revision`。

布局切换、标签切换、图层显隐和相机操作不得触发草案保存或服务端 revision 变化。

## 6. 错误处理与安全边界

- 保存失败或 409 冲突时，旧预览立即清除，生成和外部操作保持禁用。
- 无效爆源坐标不得导致未捕获异常；字段、标记和检查面板显示同一 finding。
- 关闭检查器、折叠高级区或隐藏图层不能隐藏阻断状态；顶部状态和主动作仍显示阻断原因。
- 项目切换、卸载和返回旧工作台时必须中止预览请求、释放 viewer、取消拖动和清理事件监听。
- 不修改外部动作的逐次确认、服务端 snapshot、路径约束和身份复核。
- 不启动 LS-PrePost 或 LS-DYNA 作为界面测试副作用。

## 7. 响应式与可访问性

- 宽屏：步骤轨道 + 主画布 + 右侧检查器。
- 中等宽度：步骤轨道 + 主画布，检查器使用可开合抽屉。
- 小屏：顶部步骤选择、主画布和下方检查器单列排列。

所有图标按钮有可见或辅助名称；步骤、标签、图层、折叠组和外部操作可用键盘操作。焦点顺序遵循顶部、步骤、画布工具、检查器、底部动作。颜色不是错误/警告/成功的唯一表达方式。

不修改 Phase 18C–E 建筑生成、provider 数学语义、公开 REST 路由、项目存储格式、fingerprint 语义或旧工作台 DOM。

## 9. 测试与验收

实现采用测试驱动：

- 静态合同：新布局语义、唯一 ID、标签、折叠高级区、响应式类和旧路由隔离。
- 状态测试：步骤切换不改草案，schema 字段仍闭合，JSON 默认隐藏，provider 切换清理旧值。
- Node runtime：XYZ 编辑、视图点选、拖动提交、Esc 取消、迟到事件隔离、卸载释放、保存冲突和动作门禁。
- Viewer 测试：爆源标记、三轴操纵器、图层显隐、相机保持和实例级 dispose。
- 回归矩阵：Phase 18F non-heavy、Web/static/startup、Phase 17 兼容、Node syntax、compileall 和 diff check。

三条大型 provider/asset 工作流的 fresh 最终 PASS 属于独立的软件验收证据门。界面实现完成后如纳入本轮验收，应按最终 Git commit 串行运行三项，并分别保留 JUnit XML、日志、耗时和 package fingerprint；任何一项无自然终态都不得记为 PASS。

真实 LS-PrePost 导入与 LS-DYNA 求解不属于本次界面优化；所有输出继续保持 `solver_ready=false`、`requires_project_review=true`。
