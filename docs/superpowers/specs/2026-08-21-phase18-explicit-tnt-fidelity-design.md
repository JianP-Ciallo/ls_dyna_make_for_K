# Phase 18 显式 TNT 与物理细节增强设计

状态：已实施并完成三模型 1 ms R12 初步求解验证

日期：2026-08-21

## 1. 目标

在现有“实体建筑 + 可见空气域 + 可移动爆源 + ALE/FSI 真实能量传播”基础上完成两项增强：

1. TNT 必须由可见、可审计的真实 ALE Solid 单元表示，并可在前端修改当量和位置；
2. 三个默认场景通过有物理意义的空气、结构、地面和钢筋细节达到约 45–70 MiB，而不是通过注释、重复记录或无效单元填充文件。

用户提供的外部参考文件 `2.k` 只作为体量和构造表达参考，不纳入仓库。其 65.34 MiB 主要来自 461,452 个节点、286,840 个 Solid（其中空气 160,549、结构 126,290、TNT 1）及约 61,961 个 Beam，不作为逐字或拓扑模板。

## 2. TNT 物理表示

### 2.1 质量守恒实体

- TNT 采用独立 `PART_TNT`、`MAT_HIGH_EXPLOSIVE_BURN`、`EOS_JWL` 和 `SECTION_SOLID`；
- TNT 几何为以用户位置为中心的质量守恒立方体，边长为 `(mass / density)^(1/3)`；
- TNT 体积使用与空气域共节点的结构化 HEX8 网格，默认每轴至少 3 个单元；
- TNT 所占 ALE 单元从空气 Part 中移除并改属 TNT Part，禁止空气/TNT 正体积重叠和空洞；
- `INITIAL_DETONATION` 直接引用 TNT Part，起爆点为 TNT 几何中心；
- 删除 solver-complete 路径对球形 `INITIAL_VOLUME_FRACTION_GEOMETRY` 的依赖。

这一选择与参考 `2.k` 的独立 TNT Part/实体表达一致，同时比其单一 TNT 单元提供更稳定的可见性与离散分辨率。立方体体积严格对应用户 TNT 当量，避免球体体素化造成质量漂移。

### 2.2 移动与失败边界

- 用户位置是 TNT 几何中心，可取任意有限 SI 坐标，不要求吸附旧网格；
- ALE 坐标轴显式插入 TNT 六个边界面和内部等分面，移动后重新生成共形网格；
- TNT 必须完全位于空气域内部，并与建筑、钢筋、地面保持正间隙；
- 当量、位置或网格参数改变时，预览、验证、包指纹和生成包全部失效并重新计算；
- 生成前给出安全移动包络、TNT 单元数、几何体积、实现质量和空气/TNT 分区证据。

## 3. 物理细节与文件体量

### 3.1 原则

- 45–70 MiB 是三个默认验收场景的目标区间，不是任意用户参数的强制字节合同；
- 文件大小只能通过真实节点、Solid、Shell、Beam、Set 和连接证据增长；
- 不允许字节填充、重复无效单元、改变文本格式以虚增体积，或生成后手改 K 文件；
- 若用户手工设置使模型超出预算，必须在大分配前明确拒绝。

### 3.2 分区细化

- TNT 内部：每轴至少 3 个共形 HEX8；
- TNT 邻域：按爆源尺寸和空气网格生成确定性过渡层；
- 建筑/地面 FSI 邻域：保留较细空气单元，确保表面耦合分辨率；
- 远场空气：允许逐级放粗，避免全域统一加密造成无意义求解成本；
- 地面：继续使用独立 `ground_cell_size_m`，合法范围 0.10–0.50 m；
- 空气：新增闭合范围 0.15–0.50 m，默认场景通过物理预设选择合适值。

### 3.3 三类建筑细节

- 商业超市：Solid 承重柱、墙、板与屋面；柱纵筋和闭合箍筋；墙体横竖双向钢筋；钢屋架、细长框架按物理用途保留 Beam/Shell；
- 住宅建筑：关闭非设计空层，保留真实墙柱梁板承重路径，补足楼板、楼梯/核心筒和必要配筋；
- 地铁入口：地下箱体及不透明亭体墙、顶板、底板为 Solid；玻璃、金属薄板、栏杆和细长框架按真实长细比使用 Shell/Beam；地面与入口连接清晰可见；
- 不禁止 Shell 或 Beam，只禁止与构件厚度、长细比和承重语义不符的单元族选择。

## 4. 前端

主表单直接显示：

- TNT 当量，0.1–100 kg；
- TNT 中心 X/Y/Z，单位 m；
- 空气单元尺寸，0.15–0.50 m；
- 地面单元尺寸，0.10–0.50 m；
- 细节等级和预计节点/单元/K 文件体量。

预览的 `blast_source` 层不再只显示点标记，而显示由后端权威 TNT 单元生成的有界 HEX8 几何；同时显示 TNT Part、实际尺寸、单元数、质量和起爆点。拖动爆源时使用相同权威配置路径，越界或碰撞立即阻断保存/生成。

## 5. 兼容性与身份

- 只修改 solver-complete ALE/FSI 路径，不改变 Phase 18D 三资产的默认编译指纹；
- 配置升级到新的闭合 schema，并为现有 `@2` 输入提供唯一、确定性的迁移；
- TNT 分区、细化参数和实现质量进入场景、Provider、fragment、package 和 artifact 指纹；
- Phase 18E assembler、Phase 18F Store/API/预览/保存/恢复继续使用同一规范化输入，不创建前端私有真值。

## 6. 验收

实施严格按 RED→GREEN：

1. 显式 TNT Part 必须拥有非零 Solid，空气/TNT 单元集合互斥且共形；
2. TNT 体积 × 密度必须与请求质量在浮点容差内一致；
3. `INITIAL_DETONATION` 必须引用 TNT Part，禁止 solver-complete 包继续依赖体积分数球；
4. 前端可编辑质量和位置，预览显示真实 TNT HEX8，保存/重载/失效闭合；
5. 三个默认模型实体/连接/单元族审查通过，K 文件各自处于 45–70 MiB；
6. Phase 18C–F 兼容矩阵、打包边界、Python/Node 静态检查通过；
7. 三包分别通过 LS-PrePost 导入、R12 mcheck 和严格串行 1 ms 求解；
8. 求解必须正常终止、达到目标时间、空气和建筑均出现响应、无关键字/负体积/致命错误。

即使软件和 1 ms 验证全部通过，产物仍保持 `engineering_validated=false`、`solver_ready=false`、`requires_project_review=true`，直到完成网格收敛、材料标定、真实工况时程和工程审查。
