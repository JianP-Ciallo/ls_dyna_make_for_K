# Phase 17 City Object Response and Connected Street Equipment Design

## Goal

Produce a new controlled city blast project in which every response building
and selected facility:

- receives a uniquely attributable ALE/FSI load;
- records object-level pressure, stress, and displacement evidence;
- has a pressure fringe that can be inspected in the solved `d3plot`;
- has an automatically exported LS-PrePost pressure image at a qualified peak
  response state; and
- cannot pass acceptance through a numerical-noise energy change.

The existing project and its solver outputs remain immutable historical
evidence.

## Scope

The implementation covers:

- commercial supermarket;
- residential community;
- subway entrance instances;
- traffic lights;
- other base-fixed components marked as ALE/FSI response objects; and
- movable facilities when they are explicitly included in the response
  acceptance profile.

Roads, ground-foundation plates, parking support plates, and TNT visual guides
remain fixed non-response supports in this revision. Ground response requires a
separate foundation model and is not silently added to this work.

Buildings remain single-layer structural shell models in this revision.
"Pressure entering a building" means that an exterior ALE/FSI load produces a
finite structural hydrostatic-pressure and stress response in the building
shell after the object's qualified FSI arrival. It does not mean propagation
through a meshed wall thickness or transmission into an interior ALE air
volume. Those two capabilities require solid walls and an explicit interior
domain and are deferred to a later phase.

## Coupling Architecture

Each response object receives a stable, non-empty slave segment set derived
from its exposed structural shell topology. Response-object segment sets must
be pairwise disjoint.

Each object is coupled to the common ALE air/TNT master part set by its own
`*CONSTRAINED_LAGRANGE_IN_SOLID` interface. A segment may occur in exactly one
coupling interface. The previous union segment set may be retained only as
metadata or a validation union; it must not create a duplicate coupling load.

The generated metadata binds:

- object ID;
- part IDs;
- FSI slave segment set ID;
- FSI interface/surface ID;
- shell history set ID;
- response node set ID; and
- expected postprocessing artifact names.

`dbfsi` must contain the same number of surfaces as generated response
interfaces. Every surface ID must resolve to exactly one response object.

## Structural Output Architecture

The deck enables:

- `*DATABASE_BINARY_D3PLOT` for full-field pressure, stress, and displacement;
- `*DATABASE_FSI` for per-interface pressure, force, and impulse histories;
- `*DATABASE_ELOUT` with object-level shell history sets; and
- `*DATABASE_NODOUT` with object-level free response nodes.

Shell history probes are selected from exposed, non-fixed faces. Response nodes
are non-fixed nodes belonging to the same object's structural topology.

The object response parser calculates:

- baseline-subtracted FSI pressure rise;
- peak FSI pressure, resultant force, and impulse;
- first qualified FSI pressure arrival;
- peak hydrostatic structural pressure;
- peak principal stress;
- peak displacement;
- first qualified structural response time; and
- post-arrival observation duration.

## D3plot Pressure Evidence

The solved `d3plot` remains the authoritative full-field source. LS-PrePost
postprocessing isolates one object at a time by part ID, selects structural
pressure, moves to that object's qualified peak-pressure state, fits the
object, applies an object-local finite fringe range, and exports a PNG.

An object does not pass visual evidence merely because a PNG exists. The
artifact must:

- have a valid PNG signature;
- contain non-uniform rendered pixels;
- reference the qualified run ID, object ID, part IDs, state, and time;
- be generated by a manifested server-controlled cfile; and
- be recorded in the run evidence manifest with its SHA-256 hash.

The run-level flags `pressure_cloud_recorded`, `stress_cloud_recorded`, and
`displacement_cloud_recorded` are true only when every required response object
has its corresponding qualified evidence.

## Acceptance Rules

Acceptance is fail-closed and object-level.

For every required response object:

1. The generated FSI segment count is greater than zero.
2. No FSI segment is fully translation-constrained.
3. Its DBFSI surface exists and has finite data.
4. Peak baseline-subtracted pressure exceeds both an absolute numerical floor
   and a baseline-noise multiplier.
5. Positive pressure persists for more than one sample.
6. Hydrostatic pressure and principal stress are finite and exceed their
   baseline noise floors.
7. Displacement is finite, nonzero above numerical noise, and below the
   component-specific instability limit.
8. Structural response cannot precede its own FSI pressure arrival by more
   than one output interval.
9. Distance-ordered arrivals cannot be inverted beyond the combined spatial
   and temporal sampling tolerance.
10. At least 20 ms of solved response remains after the farthest required
    object's qualified arrival.
11. Pressure, stress, and displacement visual evidence is complete.

The former `1e-6 J` MATSUM criterion remains diagnostic only and cannot satisfy
object response acceptance.

## Traffic-Light Structural Model

The traffic-light pole, mast arm, and signal head are rebuilt as one connected
load-bearing shell topology. Connections use shared nodes rather than
coincident but independent pieces.

Requirements:

- exactly one connected structural component;
- no unreferenced or free-floating shell island;
- local nominal mesh size no greater than 0.10 m;
- at least two elements across each mast junction dimension where geometry
  permits;
- only the pole-base support nodes are fixed;
- all FSI faces containing only fixed nodes are excluded;
- finite shell aspect ratios and positive element areas; and
- peak displacement is bounded relative to pole height and cannot show
  inter-piece separation.

Decorative geometry on other response objects follows the same rule: it is
either connected/tied to the load-bearing topology or explicitly excluded from
FSI and response acceptance.

## Duration

The default corrected solve duration is at least 50 ms. The required end time
is also computed from the farthest required object's qualified arrival plus a
20 ms observation window. A run that terminates earlier is incomplete even if
LS-DYNA reports normal termination.

## Mesh Convergence

The controlled campaign generates coarse, medium, and fine meshes from the same
scene and object identities. It compares, per required object:

- peak FSI pressure rise;
- peak hydrostatic pressure;
- peak principal stress; and
- peak displacement.

The convergence report records refinement ratios, monotonic or oscillatory
classification, and GCI/Richardson quantities when mathematically supported.
Missing or non-converged evidence blocks quantitative claims but does not erase
a separately passing qualitative propagation demonstration.

## Material Claim Boundary

The current `concrete_linear_elastic_demo` profile is permitted only for
software workflow, propagation, visualization, and qualitative response
acceptance. It is not a calibrated damage, failure, or fragmentation model.

Engineering prediction remains blocked unless the project provides a
manifested calibration artifact that binds material source, units, parameters,
specimen scope, and validation evidence to the run. The implementation must not
replace missing calibration with undocumented generic K&C parameters.
