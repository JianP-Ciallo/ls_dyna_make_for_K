# 多场景损伤与接触改进实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 检查五个原设计场景的板片损伤覆盖，并改善脱离连接后的运动连续性、楼板接触和耗能。

**Architecture:** 沿用现有 Worker 内的确定性位置约束网络。失去外部支承只释放连接，不预先切断内部全部黏结；转换时继承当前位姿及节点速度。增加基于空间分桶的尚存楼板/屋面接触，法向无穿透、切向摩擦耗能，并防止地下碎片穿越槽壁时被抬到地面。栏板改连实际接触的阳台板，墙片优先连相邻下排墙及近处楼板；可见基座侧墙参与损伤、底部参考楼板保持固定。版本升为 @4，旧缓存保留。

**Tech Stack:** 原生 JavaScript、Float64 计算、Float32 回放、Node 专项、pytest 包装、Edge CDP。

**Spec:** 本次用户请求：检测其他场景并继续使响应接近真实物理；沿用先前已确定的简化演示路线，自主完成，不再次启动设计确认。

## Global Constraints

- 原地保留已有修改和全部旧证据；不提交、合并或清理历史。
- 不启动原生整栋、自重、13 单元、TNT、全量、其他重型或旧生成器。
- 五个 CPU 演示各自独立计算；不改变原外观尺寸、配筋、材料参数或支承验收门槛。
- 不把实时图形动力学改进描述为校准后的实体有限元结果。

## Review Focus

1. 多楼层和地铁地下切口：落点应取实际尚存表面，避免把地下碎片抬到地面。
2. 支承失效：内部完整板允许整体下落、弯曲，不能触发瞬间全部粉碎。
3. 已移动/转动构件转换：不回到初始位置，不丢失平动或转动速度。
4. 近乎零宽墙条、扶手、车身、固定地下参考：分类必须解释清楚，不能为“全部碎裂”误接。
5. 旧结果与新版缓存：各场景隔离，新版本不得覆盖旧结果。

## 决策记录

- 本人原地执行，复用一名只读审查者；不另开工作树，不提交。这沿用用户保留工作区和减少子代理的要求。
- 审计发现 podium 的 fixed:true 同时固定了可见侧墙；本轮仅纠正演示侧墙，不改地下固定参考。
- 支承细化只处理竖向墙片、实心栏板/女儿墙，保留柱、屋顶等原始主路径；窗框和细杆仍是简化表达。
- 本轮接触处理尚存楼板及槽壁，不加入碎片之间的全接触。计算范围保持浏览器演示规模。

## 技术依据

位置约束投影后更新速度，再处理接触摩擦/恢复速度，参考 Müller 等原始论文 [Position Based Dynamics](https://matthias-research.github.io/pages/publications/posBasedDyn.pdf)。仅采用局部图形动力学思想，不宣称实现完整 XPBD 或工程混凝土本构。
