# 非线性自重平衡与诊断修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 用户已要求直接修复，在当前工作区内联实施；不另行等待计划确认。

**Goal:** 在不改变重力、质量或材料强度的前提下，使用实际宏连接本构建立初始自重平衡，保存成功与失败诊断，用微型算例验证后申请唯一三层工况重跑。

**Architecture:** 将自重平衡从仅弹性预测改为有界的分级荷载与非线性 Newton 迭代，线搜索及失败时缩小荷载增量。每级的试算均使用上个已收敛状态的材料历史，收敛后一次提交；失败回滚，不发布未平衡初始帧。独立重力模块负责残差缩放、迭代与结构化诊断，力学本构与动力计算继续共用。

**Tech Stack:** Python、NumPy、SciPy 稀疏线性代数、现有受控 worker 与 pytest 专项。

**Spec:** 用户本次要求及 `docs/superpowers/reports/2026-10-23-three-storey-first-tnt-trial.md`。

## Global Constraints

- 不跳过重力、不修改 MATERIAL 的强度、断裂能、模量或密度，不用伪造平衡力抵消残差。
- 本轮只运行小算例与相关专项；不运行三层整栋（包括仅自重）、其他真实模型、重型或全量。重跑原 10 kg / (10,-10,0) m / 250 ms / 100 s 工况前必须获得用户新确认。
- 保留所有旧输入、失败证据及用户改动；不提交、合并、清理或新建工作树。
- 求解预算包括自重；取消/时间预算在自重迭代中检查。失败诊断不得导致未平衡状态进入爆炸积分。

## Review Focus

- 损伤/塑性试探状态不得在被拒绝的 Newton 步或失败荷载级中污染已提交历史；用材料非线性微型悬臂与回滚检查验证。
- 荷载超过承载能力、无约束机构、近极限点或预算耗尽必须失败并保存诊断，不能仅靠小增量宣称收敛。
- 力与力矩分开记录、按构件特征长度缩放；零荷载、固定构件及有限转动均需有界数值处理。
- 重力引发的初始钢筋应力、损伤必须保留，进入动力阶段前复核提交后的实际恢复力，显示为初始状态而不是 TNT 引起的事件。
- worker 失败文件与成功结果都要带诊断；微型真实子进程验证完整链路，旧失败记录可读取。
