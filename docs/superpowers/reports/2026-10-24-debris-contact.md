# 碎片互撞与落地堆积验收

已在现有五场景 CPU 演示加入双向碎片接触、摩擦耗能、静止堆积及可唤醒休眠。保留原有渐进裂缝与构件损伤，不引入复杂钢筋本构。

## 实现与物理范围

- 新增 `blast_debris_contact.js`：实际有厚度的三角片/整块箱体代理、三维扫掠分桶、有限质量的双方分离、接触点冲量与转动响应、摩擦耗能。
- 高速/中面交叉及箱体采用凸体 SAT 和平移扫掠；低速三角片采用带厚度的最近顶点/边特征近似，面接触取最近点集合的中心。低速边缘为圆滑近似，不宣称完整旋转 CCD 或工程接触精度。
- 全部对象先完成积分，再统一碰撞求解；180 Hz 积分、60 Hz 接触、每次两轮接触与内部约束交替求解。接触历史覆盖两次接触之间的积分步，按代理对象存储，避免形状 ID 串用。
- 健康接缝由 bond 端点的局部焊接类保持连续。外碰撞后重新投影坐标及质量加权节点速度，避免把数值修正造成的接缝当作破坏；同板断开的碎片仍可互撞。
- 实际有支承、连续低速 12 次更新才计为静止；同健康岛全员满足持续 30 次更新后休眠。碰撞沿睡眠接触图及健康岛传播唤醒，旧接触边参与同轮求解；地面/楼板支承丢失也会唤醒。休眠碎片保留碰撞体，醒来后仍为有限质量。
- 页面回放显示静止碎片与近地堆积高度。高度是近地受支承静止接触链的最高点，包含斜置或竖立的脱落构件，不是残骸体积或工程堆积预测。
- 质量与惯量使用均一相对密度及几何体积近似，不把结构 capacity 当成质量。几何、配筋、承载参数和原有支承关系保持不变。
- 增强结果升级为 `progressive-panel-fracture@5`；旧 @4、@2 等结果键保留，对比模式仍为 `simplified-breakable-components@2`。新版帧包含经过校验的 debris 状态。

接触点速度、双向惯量与摩擦处理参考 Müller 等原始论文 [Detailed Rigid Body Simulation with Extended Position Based Dynamics](https://matthias-research.github.io/pages/publications/PBDBodies.pdf)。本次是演示级近似实现，不宣称完整 XPBD、实体有限元或标定后的钢筋混凝土结果。

## 最终验证

相关 pytest **13 项通过，43.60 秒**，见 `pytest-final.log`；不是全量回归。覆盖新增碎片小模型、五场景各 1 秒增强响应和零输入、原板片/栏板回归、页面及 API 专项。

小模型验证包括双向质量响应、全节点动能不增加、线动量守恒、已有纯转动不被拟合衰减、高速末态重叠与分离两种入射、跨接触步扫掠、同板分离片接触、外物撞击健康接缝仍连续、箱体与薄片互撞。三层厚度各 0.16 m 的薄片稳定堆高约 0.48031 m；持续静止后休眠，支承移除及新撞击均能唤醒整堆并保持分层。悬空低速片不计作堆积；中面交叉保留精细凸体路径；密集桶超预算显式停止。

真实 Edge 五场景各完成 6 秒、181 帧的强烈预设响应，共 **48 项场景/页面检查通过**。模式、旧缓存、零输入和窄屏兼容专项另 **19 项通过**。无 JavaScript/GPU 错误，固定参考在全部帧保持原位，所有失效且符合板片条件的构件均在碎裂网络中。五份实际导出 `.json.gz` 均验证原始 SHA-256 及帧内容，并确认存在真实接触、静止片和正的堆高。

## 住宅小区授权与停止条件

初始 60 秒预算内住宅小区推进到 2.8/6 秒，故停止该次验收并保存记录。用户随后当次明确批准“住宅小区最多 180 秒一轮”。本次追加仅此场景，外部进程监督覆盖整个验收，不自动重试；计算约 144.84 秒，含导出、回放、检查总计 **174.75 秒**，在授权预算内通过。授权与监督记录见 `community-180-attempt.json`、`community-180-completion.json`。

## 性能与剩余限制

密集碎片接触明显增加计算耗时，住宅小区规模约 4,027 个动态代理，仍需约 2.4 分钟计算。CPU 热点记录在 `cpu-hotspots.json`；优化移除了无关楼层接触查询、已结束脉冲重复计算及稳定堆积的部分重复求解，没有修改材料承载参数。

分桶占用、原始访问/配对、有效候选及单步时间均设显式停止保护，没有静默跳过活动碰撞。最终五场景未触发容量保护，limited 均为 0。低速最近特征与转动 CCD 限制如前所述；接触力和碎片形状仍是图形动力学近似。未加入复杂钢筋本构、完整流场遮挡或静力自重平衡，也未运行原生整栋、自重、13 单元、TNT、全量或其他重型工程案例。
