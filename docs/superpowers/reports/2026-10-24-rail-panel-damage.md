# 阳台实心栏板损伤遗漏修复

用户截图中的青色构件是实心阳台栏板。上一版将它们标记为 `rail`，但渐进碎裂的类型集合未包含 `rail`，因此仍走整块构件脱落路径。只读核对上一轮保存的实际结果：36 块栏板中 0 块进入碎裂网络，22 块整块脱落。这是实现遗漏，不能解释为这些栏板未达到损伤条件。

## 修改

- 将符合原薄板几何判据的实心 `rail` 加入碎裂网络；细长扶手和固定参考构件继续由原判据排除。
- 竖向栏板的连接锚点设在下边缘，与楼板连接位置一致。
- 结果版本统一为 `progressive-panel-fracture@3`，输出、回放校验及结果缓存使用同一常量。旧 `@2` 缓存保留，新结果单独存储。
- 未改模型几何、原有承载参数、配筋、支承或原生材料实现。并非强制所有构件碎裂；实际响应决定是否开裂、分离。

## 验证

新用例先复现旧实现遗漏，再验证修复。新增 Node 回归 8 组，包括实心/细杆/固定构件分类、下缘连接、零输入、参考响应、原三层建筑 36 块栏板接入及版本一致性。已有渐进碎裂 13 组回归继续通过。

相关 pytest 专项共 11 项通过（8.75 秒），记录见 `artifacts/rail-panel-damage-20261024-01/pytest-01.log`。

实际 Edge 浏览器专项共 17 项通过：一次简化三层建筑 6 秒响应计算耗时约 3.31 秒；36 块实心栏板全部进入网络，保存状态记录 62 条栏板裂缝、63 个已分离栏板三角片。全场节点有限，无 JavaScript 或 GPU 错误。以上数量是演示网络统计，不是工程精度结论。检查了旧缓存保留、刷新回放、模式切换、零输入及窄屏布局。记录和截图位于 `artifacts/rail-panel-damage-20261024-01/browser-01/`。

独立只读审查未发现阻塞问题。本轮没有重新验收全部五个建筑，也没有运行原生整栋自重、13 单元、TNT、全量或其他重型测试。未操作用户当前可见 Edge 页面；刷新演示并重新计算后会使用新实现。
