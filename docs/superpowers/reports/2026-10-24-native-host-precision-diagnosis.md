# 新材料检查点的宿主精度差异定位

**原因已定位：当前高精度实现只检查编译类型能力，没有保护 Python 宿主中的实际运算精度。** 独立 MinGW EXE 以 x87 64 位精度运行；本机 Python 进程初始为53位。接口仍报告支持高精度，但长双精度根搜索和三维计算中的中间运算被53位舍入，导致同一新材料点失败。

本轮只做单材料点诊断、同进程因果对照及中间产物清理。没有修改数值源码或安装修复，没有重跑整栋、13 单元、TNT、全量或其他重型测试；σ33 门槛、材料参数、配筋和支承均未修改。

## 同一新检查点最小复现

输入是 `artifacts/native-whole-gravity-precision-20261024-01/execution-01/worker/native-first-failure.jsonl`，保留原完整材料历史和五维失败试探应变。

先用已验收独立 EXE 恢复该新检查点：应变、应力、切线核对通过；`point-reproduce` 返回0，完整 `point-acceptance` 也通过，真实 σ33=+1.2252512372745716e-12 Pa，保存了非零厚度低位。说明不能仅以“新检查点不同于旧点”解释差异，需要检查宿主环境。

随后在实际精度版 Python 解释器中，导入 NumPy 和原 pyd，再加载一次性诊断桥。桥接链接现有构建缓存中的材料实现，负责在同一 CPython 线程内恢复 JSON 检查点；它不是给原 pyd 安装的新接口，也没有替换原 pyd。桥接 C ABI 仅使用 char*/int/JSON，没有跨 Microsoft ctypes ABI 传递 MinGW long double。

在同一进程、同一线程、同一检查点和同一实现下，仅切换 x87 precision-control 位；每次都恢复来时控制字。结果为：

| 调用 | 有效 CW | 原生返回 | σ33 证据 |
|---|---|---:|---|
| Python 原始53位 | 0x27f | -1 | 失败事件当前候选 -1.1097193507430408e-8 Pa，超门槛 |
| 临时64位 | 0x37f | 0 | 活材料实际 +1.2252512372745716e-12 Pa，通过 |
| 恢复53位后再次调用 | 0x27f | -1 | 再次失败 |

第一行失败事件的 `reason`、五维试探输入和**所有 root 字段**与整栋保存现场逐字段完全相同，包括57次求值、种子、候选、括区、σ33及D3333。该对照同时闭合了宿主精度与整栋首失败之间的联系。

失败返回后的活对象已保留此前试态，其 σ33≈1.54614e-11 Pa；这个返回缓存不是失败候选，不能用它宣称通过。表中失败值来自回退前诊断事件；成功值来自活材料实际响应。

## 高精度链路为何没有发挥作用

- 当前 `supportsPrecise33()` 看到 `numeric_limits<long double>::digits=64`，返回 true；这个值在53/64位运行环境中都不变。
- 实测原始 x87 CW：独立 EXE 为0x37f；Python 启动、导入 NumPy、导入实际 pyd、加载诊断桥之后均为0x27f。本轮没有发现是 NumPy 或 pyd 导入把它从64改成53；差异在这些导入前已经存在。
- 运行期 volatile 探针 `(1+2^-60)-1`：53位返回0，64位返回8.673617379884035e-19。输入和中间变量在 MinGW C++ 中计算，避免编译器常量折叠和 ctypes long double 布局差异。
- 同进程三个材料调用的能力报告始终为 true，但有效位探针随精度切换改变，材料返回同步呈 -1/0/-1。每次调用后 CW 均恢复0x27f，MXCSR 记录前后相同，五维应变没有修改，拒绝后应力变化为0。
- `_controlfp` 的抽象返回不足以替代本轮 `fnstcw` 直接读取，根日志按 double 保存的坐标也不能单独证明内部运算精度；本轮依据运行期探针和可逆因果对照得出结论。

此前精度专项主要启动独立 `NativeMaterialRegression.exe`，因此覆盖的是64位环境，确实漏掉了 Python 宿主有效精度这一边界。旧检查点在 Python 53位下也恰好通过（σ33=+1.8625576855575005e-9 Pa），64位下则为-4.191998527816598e-12 Pa；所以仅增加旧点测试仍可能漏检。新检查点的宿主内测试必须成为回归用例。

## 修复方案（本轮未实施）

详见 `docs/superpowers/plans/2026-10-24-native-host-precision-guard.md`。

推荐在本地数值调用栈内加入可嵌套的扩展精度 RAII 保护：保存当前线程 CW，只将精度控制位置64并读回核实，成功、失败和异常路径均恢复来时控制字；保持舍入模式、异常掩码和 MXCSR 控制位。保护必须覆盖 PlateFiber 根算术、三维隐式精度求值和高低位组合入口，不能只在计算完成后提高精度，也不能永久修改 Python 进程环境。

同时补齐进入/有效精度与根高低位诊断，能力不足时给出明确失败；继续以活材料实际 |σ33|≤1e-8 Pa 接纳。轻量验收增加本轮新检查点在 CPython 同线程的53/64位来时环境、嵌套和异常恢复、不同线程，以及真实材料 σ33、切线和状态历史。独立 EXE 回归和实际 pyd 最小板片专项继续保留。

该方案保持材料法则、参数、外部五维输入和门槛不变。修复完成仍只能先声明材料与轻量范围通过；整栋等重型复验要另行明确授权。
