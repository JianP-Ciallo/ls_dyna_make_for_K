## 1. 项目定位

本项目面向以下两个相互衔接的方向：

- 硕士论文方向：**面向爆炸冲击场景的智能有限元建模方法与仿真系统研究**。
- 专利方向：**一种基于城市语义模型、多保真爆炸仿真与不确定性驱动局部精化的周边建筑快速影响评估方法**。

系统目标不是让 AI 任意拼写 LS-DYNA 关键字，而是让 AI 或 Web App 在受控场景、组件、材料和物理动作范围内选择参数，再由项目后端统一完成：

1. 语义解析与参数确认。
2. 模型组合和 K 文件生成。
3. 结构化检查、来源记录与项目管理。
4. Web 三维预览和 LS-PrePost 导入验证。
5. 经用户逐次授权后，提交 LS-Run/LS-DYNA 求解。
6. 读取结果并形成对象级影响评估。

始终区分三个结论：

- **能够生成**：后端可以输出结构完整的项目和 K 文件。
- **能够启动求解**：关键字读取及初始化门禁通过。
- **达到工程精度**：还需要材料标定、网格与空气域敏感性、试验对照和不确定性分析。

## 2. 不可破坏的基线

- AI 只调用项目公开工具，不直接代写或修改生成后的 `model.k`。
- 场景预设、组件库、材料库、载荷、接触、约束和求解动作相互分层。
- 生成、预览、打开 LS-PrePost、启动求解是四个独立动作。
- 未经用户对本次运行明确授权，不启动 LS-Run 或 LS-DYNA。
- 外部 K 文件和任意关键字片段不能直接进入可信组件库。
- 项目修改后，旧预览、旧求解结果和旧影响评估必须标为陈旧。
- `checks.json` 是基础门禁，不等同于工程验证报告。

## 4. Phase 16：城市快速影响评估

### 4.1 Phase 16A：简单、可解释的对象级评估

目标：把城市语义对象与计算结果对应起来，输出“哪个对象受到多大影响、为什么得到该等级”。

当前状态：

- 16A.0 已实现：建筑、地铁入口、车辆、道路、爆源等稳定语义 ID。
- 16A.1 已实现基础合同：对象指标、检查结果和缺失结果语义；仍缺经过真实结果验证的通用 d3plot 对象提取器。
- 16A.2 已实现规则评估：低、关注、较高、严重、无法评估；阈值仍需试验或文献标定。
- 16A.3 已实现：对象级评估面板和场景联动。
- 16A.4 已实现：结构化评估报告。
- 16A.5 待完成：在用户逐次授权下进行真实求解验收和阈值校核。

完成门槛：

- 结果提取必须绑定语义对象，而不是只读全局最大值。
- 无 d3plot、结果过期或对象映射缺失时必须返回“无法评估”。
- 评估结果必须记录模型版本、求解来源、提取方法和规则版本。

### 4.2 Phase 16B：多保真与不确定性驱动精化

目标：先用低成本模型筛选风险，再对不确定或高风险局部自动建立高保真任务。

当前状态：

- 16B.0-B.5 的任务合同、候选区域、置信度和精化建议工作流已建立。
- 16B.6 暂未验收：需要独立城市布置的多次真实高保真结果，才能校核筛选稳定性和置信度。
- Phase 16B 不是机器学习已训练完成的声明；当前仍是可解释规则与任务编排基线。

完成门槛：

- 同一场景至少具备低、中、高三档可追溯任务。
- 低保真漏判率、排序一致性和精化收益有真实样本证据。
- 用户可以查看“为什么精化该对象”和“精化前后结论是否改变”。

## 5. Phase 17：城市语义场景编辑

### 5.1 已完成基线（17.0-17.12）

- 城市对象语义清单和稳定对象 ID。
- 草案编辑、参数更新、撤销/重做和新项目生成。
- Web 三维视窗中的对象选择、平移/旋转控制和对象状态提示。
- 编辑前后相机姿态保持，避免每次应用修改都重置视角。
- 编辑动作记录、草案版本和旧结果失效提示。
- 城市专用检查已接入基础 `checks.json`，避免新场景绕过老工具。

### 5.2 Phase 17.13：车辆与地铁入口独立移动

状态：**本批代码、单元测试和浏览器验收已完成。**

范围：

- 每辆停车场车辆拥有独立对象 ID，可分别修改 `X/Y/Rz`。
- 车辆在求解语义中保持可运动，不因编辑定位被错误固定。
- 地铁入口可修改 `X/Y/Rz`，基础在求解语义中保持固定。
- 禁止车辆离开停车场支承面，禁止地铁入口离开地面支承面。
- 禁止用户通过编辑器给贴地对象设置悬空高度或倾覆姿态。
- 应用变换时保持当前相机视角，并使旧结果失效。

验收：

- 移动车辆 1 不得连带移动车辆 2。
- 地铁入口和车辆可在同一草案中分别移动。
- 支承面越界、碰撞或非法自由度必须在生成前明确报错。

### 5.3 Phase 17.14：受控组件库加入城市

状态：**车辆、地铁入口多实例及首个现有模型库构件已完成受控增删闭环；更多组件类型仍在实施。**

设计原则：

- 使用统一组件目录，不接受任意 K 文件片段。
- 组件必须声明几何、材料接口、允许移动方式、支承面、碰撞包围盒、ALE/FSI 兼容性和结果对象类型。
- 现有四个受控场景继续保留为验证预设，组件编辑是其上的受控扩展。

第一批：

- 组件目录已增加城市兼容元数据。
- Web 编辑器已加入“场景对象 / 组件库”切换。
- `parked_vehicle` 可从预定义停车位加入场景，并生成不随数组顺序变化的稳定语义 ID。
- 车辆实例支持服务端受控新增、复制和删除；前端不能直接拼接组件数据。
- 删除中间车辆后其余实例不重新编号，接触集合和对象映射按当前实例重建。
- 组件级新增、复制、删除支持撤销/重做，并记录修订号和操作来源。
- `subway_entrance` 支持保留首个兼容 ID 的多实例新增、复制、删除和独立移动；场景至少保留一个入口。
- 现有模型库 `shell_box` 已作为钢制防护箱接入城市，可新增、复制、删除和贴地移动。
- 钢制防护箱加入后自动进入固定节点集、ALE/FSI 段集和 Phase 16 对象级影响映射；删除最后一个实例后不保留悬空引用。
- `solid_block` 暂不开放城市放置。城市编译器会主动拒绝没有显式 FSI 外表面提取的实体组件，避免“预览存在但冲击波未耦合”的假闭环。

后续批次：

- 受控钢板、墙体、路障和简化建筑构件。
- 放置幽灵预览、支承高亮、碰撞提示和吸附。

### 5.4 Phase 17.15：物理依赖重建与全链门禁

状态：**车辆、地铁入口和壳体库构件的依赖重建门禁已完成；实体构件外表面提取仍待实施。**

任何组件新增、删除或移动后，后端必须重新构建并检查：

1. Part、Section、Material 和语义对象映射。
2. ALE 材料组、爆源初始化和空气域包含关系。
3. FSI 耦合段集、接触、固定约束和自由运动对象。
4. 数据库输出、对象级结果请求和影响评估映射。
5. 支承、碰撞、越界、重复 ID、悬空和无效材料。
6. 项目来源、草案修订号、模型哈希和旧结果失效状态。

当前已实现：

- 新增、复制和删除车辆后重新生成语义对象、Part 映射及车辆接触集合。
- 新增、复制和删除地铁入口与钢制防护箱后重新生成固定约束、FSI 耦合段集和对象级结果映射。
- 支承面、碰撞、场景边界、重复 ID 和悬空变换引用在编译前拒绝。
- 组件布局变化会更新布局指纹，使旧项目、旧结果和旧影响评估失效。
- 结构撤销/重做恢复完整草案和物理依赖，不只恢复前端显示状态。
- 组件操作历史进入项目来源记录，并通过严格字段和数量校验。

仍待通用化：

- 实体墙体、实体路障等组件的外表面提取、FSI 段集和材料/截面映射。
- 更多壳体墙体、钢板和简化建筑构件的受控放置合同。
- 组件属性面板、放置预览、吸附与碰撞原因可视化。

验收门槛：

- 新增组件后可以通过静态检查、模型解析和 Web 预览。
- 删除组件后不存在悬空引用。
- 撤销/重做能恢复组件及其物理依赖。
- LS-PrePost 导入验证需要用户主动触发。
- LS-Run/LS-DYNA 只在用户对本次模型明确授权后启动。

## 6. Phase 17 Web 交互目标

右侧编辑工作区采用三个视图：

- **场景对象**：选择、定位、复制、删除现有实例。
- **组件库**：按类别浏览允许加入城市的组件。
- **属性**：显示尺寸、材料、位置、方向、支承和求解语义。

交互要求：

- 添加组件前显示半透明放置预览。
- 合法支承面高亮，碰撞或越界以明确颜色提示。
- 数值输入和视窗拖动共享同一草案，不产生两个真源。
- 应用修改不改变用户当前观察视角。
- 生成前显示组件数量、爆源、约束、自由对象和检查摘要。

## 7. Phase 18：独立精细化建筑爆炸建模

### 7.1 锁定范围与系统边界

Phase 18 建立一条新的“单建筑精细化爆炸”工作流，目标是从建筑空间和结构语义重新生成具有真实内部空腔、多结构体系构件、钢筋/连接与非承重构件的可审核建筑模型，并在独立、可配置的工况中完成载荷、空气域、耦合、预览和验证闭环。

Phase 18 的范围固定为：

1. **Phase 18A**：`2.k` 大文件流式拆解与资源清单。
2. **Phase 18A-1**：梁、柱、楼板、基础构件级独立模型资源与既有场景兼容调用。
3. **Phase 18B**：材料、截面、曲线、Part 和耦合关系的审核入库。
4. **Phase 18C**：建筑空间语义与多结构体系精细建模内核。
5. **Phase 18D**：旧模型库全部建筑类资产的多体系精细语义重建版本。
6. **Phase 18E**：独立、可配置且模块化的精细建筑爆炸工况引擎。
7. **Phase 18F**：schema 驱动的精细建筑设计工作台、预览和验证闭环。

以下内容明确不属于 Phase 18：

- 城市场景、城市生成器、城市对象编辑器及其粗糙建筑资产不做改造。
- Phase 18 不从城市粗模型自动升级或局部替换为精细模型。
- 城市场景的 ALE/FSI、对象级影响评估和多保真任务合同不因 Phase 18 改变。
- 精细化模型与城市粗模型不共享结果标识、网格指纹或验证结论。
- Phase 18 不声明任何材料卡已经达到工程爆炸损伤预测精度；工程标定仍需试验、文献和真实求解证据。

场景边界固定为：

| 场景 | 用途 | 建筑保真度 | 入口与编译链 | Phase 18 是否修改 |
| --- | --- | --- | --- | --- |
| `city_street_blast` | 城市尺度快速建模与对象级影响评估 | 既有粗糙建筑模型 | 既有城市生成器 | 否 |
| `refined_building_blast` | 单建筑精细化爆炸分析 | 按结构体系生成 Solid/Shell/Beam、钢筋与连接 | 独立精细建筑＋工况编译链 | 是 |

### 7.2 总体架构与阶段依赖

Phase 18 按“外部资源隔离、审核入库、建筑内核、具体建筑、独立场景、交互闭环”的顺序推进：

```text
只读 2.k
  -> 18A 流式索引与候选资源清单
  -> 18A-1 梁/柱/楼板/基础独立构件包与兼容适配器
  -> 18B 人工审核后的材料/截面/曲线/Part/耦合资产
  -> 18C 建筑空间语义＋多结构体系生成内核
  -> 18D 商业超市/住宅社区/地铁入口多体系精细建筑资产
  -> 18E refined_building_blast 独立可配置工况引擎
  -> 18F schema 驱动的工作台、预览、检查与生成闭环
```

阶段门禁遵循以下规则：

- 18A 未证明源文件身份、计数和依赖关系正确前，不允许进入 18A-1 构件拆分。
- 18A-1 未证明四构件依赖闭合、源结构可重组和既有场景兼容前，不允许作为可选模型资源发布。
- 18B 中未审核或依赖不闭合的资源只能留在隔离审计区，不得被 18C 使用。
- 18C 的空腔拓扑、多体系构件/连接、体系专属网格和可暴露表面合同未通过前，不开始 18D 建筑精细版本建模。
- 18D 未通过空间、承重路径、钢筋/连接、网格规模和 LS-PrePost 导入门禁前，不进入 18E 工况装配。
- 18E 的独立场景输出和物理依赖未闭合前，18F 不开放“生成可求解项目”。

### 7.3 Phase 18A：双层钢筋混凝土框架爆炸参考模型流式拆解与资源清单

目标：在不把 68.5 MB 源文件整体读入内存、不修改源文件的前提下，建立可复核的关键字索引、网格统计、依赖图和候选资源清单。

源文件基线：

- 规范名称：双层钢筋混凝土框架爆炸参考模型；规范 ID：`two_storey_rc_frame_blast_reference`。
- 只读来源：由导入命令显式提供 `2.k` 文件路径；项目和发布包不保存本机绝对路径。
- 文件大小：68,514,255 字节。
- SHA-256：`C1C02A9E832852854B47CD3720BC9348CF48989484D25E1A54036836D0697A22`。
- 源单位：`tonne-mm-s-N-MPa`；项目规范化单位：`SI_m_s_kg_N_Pa`。
- 独立审计基线：461,452 个节点、348,801 个单元，其中 286,840 个 Solid、61,961 个 Beam。

拆解器职责：

- 逐行更新 SHA-256、字节数、行数和关键字计数，不使用全文件 `read_text()` 或 `splitlines()`。
- 同时支持 LS-DYNA 固定宽度字段、逗号字段、续行卡和带 `TITLE` 的关键字变体。
- 索引 Node、Solid、Beam、Part、Section、MAT、EOS、Curve、Set、约束、载荷和受约束耦合关系。
- 区分 Beam 的 N1/N2 拓扑节点与 N3 方向节点；禁止把 N3 同坐标节点盲目合并。
- 检查重复节点 ID、重复单元 ID、缺失节点引用、孤立节点、重复坐标、重复连通性和悬空资源引用。
- 为每个候选资源保存源关键字、原始 ID、源行范围、原始值、源单位、引用者和内容哈希。

### 7.7 Phase 18E：独立、可配置的精细爆炸工况引擎

目标：建立独立项目类型 `refined_building_blast@1`，将建筑工件与爆炸工况分开管理。它拥有自己的 schema、存储目录、工具/API 命名空间、编译器、验证器、预览适配器、缓存、结果 ID 和失效规则。

与其他爆炸工况实现保持严格隔离：不调用、不继承、不修改其他工况生成器；不读取对方的对象数组、布局草案、工况参数或结果。只共享中性材料/截面/模型资源、网格原语、关键字底层写入器和通用检查核心。依赖边界测试禁止两类工况包互相导入。

首发同时提供三种 `BlastLoadProvider`：

1. `explicit_ale_fsi`：显式炸药＋空气域＋起爆＋FSI，用于高保真工况。
2. `lbe_segment`：经验爆压施加到选定表面，用于快速预览、参数筛选和对比。
3. `imported_pressure_history`：导入试验或外部计算的压力—时间数据并映射至表面集。

三者拥有独立 schema、验证器、关键字片段和证据清单。不支持的组合明确拒绝，不得静默降级。

生成器固定拆分为：

```text
ScenarioDraft / Preset + Overrides
  -> BuildingPlacementCompiler
  -> SupportAndGroundCompiler
  -> BlastSourceCompiler
  -> FluidDomainCompiler
  -> BoundaryCompiler
  -> InteractionAndFSICompiler
  -> SolverControlCompiler
  -> OutputRequestCompiler
  -> ProjectAssembler
  -> CrossModuleValidator
```

每个模块只输出自己的不可变关键字片段、依赖和 manifest，不直接修改其他模块。`ProjectAssembler` 统一分配 ID、Include 顺序并闭合跨模块依赖。不得继续向现有大型装配、schema 或通用工具文件堆叠精细工况逻辑。

用户可配置层级：

1. **内核不变量**：单位、ID、依赖闭包、基本网格质量、爆源包含与非法重叠等不可绕过。
2. **审核预设**：建筑原型、结构体系、材料组合、网格、空气域、爆源和输出预设。
3. **项目覆盖**：轴网、层高、构件、洞口、材料、连接、网格、装药、起爆、空气域、支承、控制和输出。
4. **专家扩展**：用户材料、局部网格区、结构化覆盖和受控 Include；须通过关键字允许列表、路径隔离、ID 冲突和依赖闭包检查。

同一建筑支持 `ScenarioSet`：外部、内部、半封闭和参数组合工况分别生成 K 文件、指纹和结果。只修改爆源不重建建筑网格；修改结构体系才使建筑和所有下游结果失效。

18E 验收门槛：

- 无任何其他工况配置时仍可独立生成、预览和验证。
- 三种载荷提供器分别通过最小夹具、依赖闭包和失败输入测试。
- 内部/外部/半封闭工况根据洞口状态生成正确的流体暴露面。
- 爆源在允许流体域内且不与结构非法重叠；域边距、边界和 FSI 通过显式检查。
- 规模预测与最终节点/Solid/Shell/Beam 清单一致。
- 每个工况的用户覆盖、预设版本和确认记录可追溯。

### 7.8 Phase 18F：schema 驱动的设计工作台与验证闭环

目标：提供与其他工况编辑流程分离的精细建筑工作台。工作台不固定为一套不变的六步窗口，而是根据结构体系和 `BlastLoadProvider` 的 schema/能力动态显示：

1. 建筑空间与洞口；
2. 结构体系与承重构件；
3. 钢筋、钢构连接或组合连接；
4. 非承重构件；
5. 材料、截面和失效模型；
6. 网格与局部加密；
7. 载荷、爆源、空气域、边界、相互作用和输出；
8. 错误/警告、规模预算、版本确认和生成。

“审核预设→结构化覆盖→专家扩展”三层交互共用同一数据真源。预览需分层显示空腔、主体结构、钢筋/连接、非承重构件、内外流体暴露面、爆源、空气域和边界。

即时验证包括 schema、空间/洞口拓扑、承重路径、保护层/连接、网格质量、资源闭包、爆源/域/边界、规模和版本失效检查。错误阻断生成，警告需用户确认，确认写入项目来源记录。

草案、预览、正式生成、打开 LS-PrePost 和启动 LS-DYNA 保持独立动作；打开外部程序和求解必须逐次获得用户授权。

18F 验收门槛：独立项目/API/存储/预览边界成立；不同体系和载荷提供器只显示适用字段；草案可保存/恢复/版本化；预览统计与最终 K 清单一致；结构、工况或资源改变后旧结果自动标记为过期。

### 7.9 已确认与仍需用户审核的设计规范

已确认：

- 不允许用旧外壳填充成实心建筑；精细建筑必须重建空间、洞口、承重路径和非承重构件。
- 允许不同建筑使用不同结构体系，不强制统一为 RC。
- 建筑范围继续覆盖商业超市、住宅建筑和地铁入口；非建筑基础组件不进入 18D。
- 三种载荷提供器 `explicit_ale_fsi`、`lbe_segment` 和 `imported_pressure_history` 同时纳入 Phase 18E 首发路线。
- 工况使用“审核预设＋项目覆盖＋专家扩展”，不将建筑、爆源、域和输出写死。
- 建筑内核与爆炸工况分离；工况生成器按模块拆分，不建立整体巨型生成函数。
- 原 RC 三档网格数值仅作为 `rc_reference_profile`，其他体系需单独审核。

仍需分批提交用户审核：

- 各建筑原型的默认/备选结构体系，以及具体轴网、层高和构件尺寸。
- 适用的混凝土、钢结构、组合结构、防护和爆炸设计规范名称/版本。
- RC 配筋、钢结构节点、组合界面和连接简化等级。
- 围护、门窗、隔墙、楼梯、货架/固定设备等非承重构件的默认包含档位。
- 各体系网格档位、连接区加密、质量阈值和规模预算。
- 内部/外部/半封闭工况的默认装药、位置、空气域、边界、FSI、LBE 和压力时程映射规则。
- 材料标定、网格敏感性、试验对照指标和允许误差。

未审核预设只能标识为研究/流程验证候选，不得标识为工程验证模型。

### 7.10 Phase 18 总体验收与完成定义

Phase 18 完成必须同时满足：

- 18A/18A-1/18B 的来源拆解、构件包和审核资源保持可追溯、可重复生成且依赖闭合。
- 18C 能生成真实空腔与至少首批五种结构体系的最小可验证建筑，各后端的构件、钢筋/连接、网格和表面清单闭合。
- 18D 的商业超市、住宅建筑和地铁入口多体系精细资产通过空间、承重路径、清单、预览和导入门禁。
- 18E 的独立项目在无其他工况配置时可运行；三种载荷提供器及内部/外部/半封闭工况通过模块、依赖和隔离验收。
- 18F 完成从审核预设、用户覆盖、分层预览、检查、规模预算、生成到外部验证证据的闭环。
- 依赖边界测试证明精细建筑包、精细工况包和其他工况生成器未发生跨域导入或默认行为改变。
- 生成、预览、打开 LS-PrePost 和启动 LS-DYNA 保持独立动作，求解始终逐次获得用户授权。
- 所有工程精度声明都有材料标定、网格敏感性、试验/文献对照和真实求解证据；无证据时保持 `requires_project_review=true` 或“无法评估”。

## 8. 验证与发布门禁

当前执行规则以根目录 `AGENTS.md` 为准：按改动选择相关专项，并如实记录未运行、跳过或中断。可使用默认轻量 smoke，不把全量回归或重型案例作为每次合并的固定条件。

全量回归、真实重型案例及慢速生成检查须先说明范围与预计耗时，取得用户当次明确同意后再执行；不得通过其他入口绕过授权。前端、评估/解析和建模改动分别按相关页面/API、单元与保存结果回放、小规模生成验证选择专项。

按需且需用户授权：

- LS-PrePost：真实导入、keyword reader 消息和后处理显示验证。
- LS-Run/LS-DYNA：关键字读取、初始化或完整求解。

真实求解不得作为普通单元测试的隐式副作用。
