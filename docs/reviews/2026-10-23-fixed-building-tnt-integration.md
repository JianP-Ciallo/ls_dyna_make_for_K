# Fixed-building TNT interface integration

The user approved adding the retained TNT + air + FSI workflow to the current interface. The current main-project UI was copied as the implementation baseline. The three-column layout, four editor tabs, building preview, navigation styling and footer actions are retained. The CPU response pages, backend, API and data are outside the change.

The default scenario page provides outdoor TNT position, dimensions or mass, initiation time, air-grid settings, initial door/window states, monitors and output settings. The user subsequently clarified that TNT must not enter the building. The whole cylinder is checked conservatively against the building outer envelope, including tangency, resolved mass-input radius and vertical overlap. Save, estimate/preview and export all enforce this policy; manually submitting indoor mode is rejected. Historical indoor scene IDs remain readable and cannot be overwritten, previewed or exported. Rejected old indoor browser drafts remain intact and can be downloaded before creating a new outdoor scenario.

The TNT model view now uses the project's existing local Three and OrbitControls dependencies: left drag rotates, right drag pans and the wheel zooms. Both 3D and top-view buttons are presets; rotation remains enabled. Changing TNT fields does not reset the camera. The camera pose, target and zoom are preserved in same-tab drafts and restored on reload. Only semantic component geometry is drawn; this does not generate finite-element meshes or run a solver.

The orange TNT marker and actual cylinder can now be dragged in the model to adjust X/Y at fixed height. Accepted positions update the fields and invalidate the previous preview. The entire movement segment is checked against the building envelope using the segment-to-rectangle minimum distance and cylinder radius, so a fast pointer move cannot jump through the building. Invalid candidates retain the last legal position. Escape, lost pointer capture and window focus loss restore the drag origin. The camera is suspended during object dragging and restored afterwards; background orbit/pan and wheel input, including over the marker, remain available. Dragging sends no export or solver request, and historical read-only scenes cannot begin a drag.

A separate ↕ height handle now adjusts clearance above ground while keeping X/Y fixed. Its drag-start metres-per-pixel scale makes upward/downward input usable in both oblique and top views. The full cylinder at the candidate height and the vertical swept interval are checked before accepting movement; ground penetration and air-buffer violations are rejected. Valid changes synchronize the height field and invalidate preview. Cancellation restores all three position fields through the existing capture/OrbitControls lifecycle. No backend endpoint, native geometry or CPU source changes are required.

Existing external-pressure scenarios remain available through the explicit legacy link, and a legacy scene URL is recognized and redirected to the preserved page. TNT scene IDs use `tnt_scene_id`, separate from the existing shared `scene_id`, so navigation does not forward a TNT identity to unrelated workflows. Drafts have a separate `tnt:` identity. This follow-up changes no shared navigation adapter or CPU source.

The retained registered template is deployed as a portable static resource, with all 16 native K hashes and semantic index preserved. Its six structural inputs must match the existing building resource. Source algorithms were isolated under `architecture/tnt_native`; only the required pure helpers were extracted. The source hashes are recorded in that package's provenance file. No existing legacy generator was overwritten, no actual whole-building mesh was regenerated, and production NQUAD remains 2.

Opening, saving and previewing use metadata and axis estimates. They do not unpack/parse the full FE mesh or compute material fractions. A separate, confirmed K generation task performs the native checks and export. The confirmation shows the current scope and grid budget, and clearly labels generation timing as an unmeasured rough estimate. No native solver endpoint is provided.

Pressure curves belong to the result view. A user selects an existing result directory using a local folder dialog; the client cannot submit an arbitrary path. All 16 native input hashes must match the selected exported version before binout is read. Curves retain native times, reference pressure and actual monitor coordinates. Their label is cell-mean hydrostatic pressure, not an unsupported claim of all-time air-material pressure. CSV is generated separately from the K package, and text formula prefixes are neutralized.
